## §1. Null-безопасность (пункт 3 плана): «ненулевые указатели по умолчанию»

**Null-безопасность (пункт 3 плана): «ненулевые указатели по умолчанию».**
Обычный `T*` не может быть `нуль` (ни `= нуль`, ни без инициализатора);
nullable — только `возможно<T*>`, разворот под охранником `если (п != нуль)` или
`если (п == нуль) … иначе`. Для этого добавлен оператор `!=`.

## §2. Охват `возможно` — только указатели

**Охват `возможно` — только указатели.** Опция-над-значениями
(`возможно<целое>` с флагом присутствия) намеренно **отложена** — отдельная
фича, другое представление.

## §3. `возможно<T*>` над ИМЕНОВАННЫМИ типами

**`возможно<T*>` над ИМЕНОВАННЫМИ типами** (структура/перечисление/`внешний
тип`), не только примитивы. Нужно для интеропа с C: opaque-хендлы
(`возможно<display*> д = нуль`, потом присвоение из фабрики). Реализовано во
всех трёх позициях типа (объявление/параметр/возврат): `разобрать_возможно`
принимает именованный тип через `съесть_именованный_тип`; `нуль` совместим с
указателем на структуру (правило поднято ДО ветки структуры в
`совместимы_для_присваивания`); доступ к полю nullable-структуры (`у.поле` =
`у->поле` в C) — **разыменование**, поэтому под тем же охранником
`если (у != нуль)`, что и индексация (null-narrowing снимает `может_быть_нуль`).
Без охранника — ошибка «может быть нулевым». Тесты: `возможно_структура`,
`возможно_структура_без_охраны`, `структура_указатель_нуль`.

## §4. Конвертер C→Konda — отдельный проект `konda-from-clang`

**Конвертер C→Konda — отдельный проект `konda-from-clang`** (сосед этого репо,
Python + `clang -ast-dump=json`). В этом репо конвертера **нет**: проверки — в
транспиляторе, конвертер только переводит и сам себя проверяет прогоном
транспилятора (verify-by-default). Ручное управление памятью → `malloc`→
`выделить`/`срез`, `free` снимается (autofree).

## §5. Интерфейс библиотек (безопасный путь 2):

**Интерфейс библиотек (безопасный путь 2):** типизированный `.и` c примитивами,
`срез`, указателями и владением; транспилятор сам линкует `.so` (rpath).

## §6. Макросы — только безопасная условная компиляция

**Макросы — только безопасная условная компиляция** (`макросы.c`): `#if/#ifdef/
#ifndef/#elif/#else/#endif/#define` (+ русские `#если/#опр/#не_опр/#иначе_если/
#иначе/#конец/#определить`), `-D ИМЯ[=знач]`. Это выбор веток AST по флагам, не
текстовая подстановка → включённый код проходит все проверки. **Функциональных
макросов и подстановки значений в код НЕ делать** — небезопасно; для констант — `конст`.

## §7. Имена в C — как есть, без манглинга/неявных имён

**Имена в C — как есть, без манглинга/неявных имён.** Пользователь не хочет
транслитерации/переименования функций: кириллические идентификаторы уходят в C
как есть (расчёт на UTF-8-идентификаторы C23). Значит роадмап-пункт «стабильная
транслитерация в ASCII» **снят для функций** — не генерировать неявные имена.

## §8. Побитовые операции `& | ^ << >> ~` — реализованы

**Побитовые операции `& | ^ << >> ~` — реализованы** (целочисленные, нулевая
рантайм-цена, статически безопасны; float/указатель/срез отвергаются). Ложатся
в инвариант «безопасность статическая, скорость C». Приоритеты как в C.

## §9. Перегрузка операторов — реализована

**Перегрузка операторов — реализована** (`Тип оператор+(Л а, П б) { … }`;
`оператор` — контекстное слово). Набор: `+ - * / % == != < > <= >=`.
Нулевая рантайм-цена: `а + б` → вызов манглированной функции
`_опер_<опкод>_<тип1>_<тип2>(а, б)`, статически (резолв в семантике по типам
операндов). Правила статические: ровно 2 параметра **по значению**, хотя бы
один операнд — **структура** (примитивные операторы не переопределяются);
`&&`/`||` не перегружаются (короткое замыкание). Заодно закрыта латентная
дыра «структура `==` структура» (раньше `тип_бинопа` ошибочно принимал за
`целое32` → битый C). Ложится в инвариант «безопасность статическая,
скорость C». Детали — `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md` §«Перегрузка
операторов».

## §10. Потоки: модель «передача владения», без разделяемого состояния

**Потоки: модель «передача владения», без разделяемого состояния.** (Ранее
потоки были отложены; курс изменён.) Поток получает данные **только по
значению или перемещением** (`владеет`-семантика). Разделяемое изменяемое
состояние **нельзя выразить** → гонки данных невозможны *по построению*,
статически, с нулевой рантайм-ценой (инвариант №1). Опирается на готовый
path-sensitive анализ move в `владение.c`. Синтаксис: `поток<T>`,
`запустить(ф, арг)`, `присоединить(п)`. Статические правила: функция потока
НЕ может иметь `изменяемый`/`вывод` (это указатели в кадр вызывающего →
повисли бы + гонка); аргумент-срез перемещается (у запускающего доступа нет);
`присоединить` потребляет дескриптор (двойной join — use-after-move).
**Shared-memory модель в стиле Rust отвергнута**: она требует borrow-checker,
а он сознательно исключён из дизайна Konda.

## §11. Каналы `канал<T>` — ОТЛОЖЕНЫ

**Каналы `канал<T>` — ОТЛОЖЕНЫ** (осознанно, а не «не успели»). Они дают ровно
одно: общение во время жизни потока (стриминг, пул воркеров, конвейеры).
Разделение труда: fork-join `запустить`/`присоединить` покрывает независимые
задачи, а параллелизм данных и map-reduce — `параллельно для` **с редукцией**.
Цена каналов высока: (1) появляется **рантайм-библиотека** (мьютекс+condvar+
буфер) — против духа «генератор обычного C без своего рантайма»; (2) вносят
**взаимоблокировки** — первый класс багов, который Konda статически
предотвратить НЕ может (обещание «нельзя допустить ошибку памяти» формально
цело, но защиты нет). Вернуться к ним, когда появится реальная задача со
стримингом.
*(Исправлено 17.07: раньше здесь стояло, что fork-join покрывает и map-reduce.
Это было неверно — reduce был запрещён как «запись во внешнюю переменную», а
собрать его вручную мешали статическое число потоков, один аргумент и
отсутствие подсрезов. Обоснование стало правдой только с редукцией.)*

## §12. Асинхронность (async/await) — ОТЛОЖЕНА

**Асинхронность (async/await) — ОТЛОЖЕНА**, обоснование то же, что у каналов, и
сильнее. Каналы отвергнуты за рантайм-библиотеку (мьютекс+condvar); async
требует рантайма **несопоставимо большего** — цикл событий, epoll, таймеры,
планировщик. Принять async, оставив каналы отложенными «из-за рантайма», было
бы непоследовательно. Плюс async решает проблему, которой у языка ещё нет
(I/O-конкурентность), при нерешённой той, что есть — пригодность имеющегося
параллелизма. **Связка (не потерять):** если однажды рантайм для async всё же
принимается, каналы автоматически теряют своё главное возражение и подлежат
пересмотру — эти два решения стоят и падают вместе. Условие возврата: реальная
I/O-задача **и** явное решение по рантайму. Роадмап — `ПЛАН_ПАРАЛЛЕЛИЗМА.md`.

## §13. Типизированные слушатели (`слушатель<T>` + доверенный трамплин) — ✅ РЕАЛИЗОВАНЫ (фаза 1, тип-безопасность)

**Типизированные слушатели (`слушатель<T>` + доверенный трамплин) — ✅
РЕАЛИЗОВАНЫ (фаза 1, тип-безопасность).** Сняли крупнейший блокер GUI-кода:
колбэк с `void *data`, кастуемый в теле к типу (`struct T *t = data`). Каст
уходит в ОДНУ сгенерированную C-функцию (трампулин), а `T` там — тип, заявленный
при регистрации и проверенный семантикой. Три конструкции: тип слушателя
(`внешний слушатель<T> Имя для C_listener {…}` — контекстные `слушатель`/`для`),
экземпляр (`Имя л = { поле = колбэк }`), регистрация (`слушать(add_listener,
объект, экземпляр, данные)` — контекстное `слушать`). **Кодоген — пред-проход
`кодоген_слушателей` (как шимы потоков):** на каждый экземпляр эмитит трампулины
(`static void _трамп_<экз>_<поле>(void*data, …) { колбэк((T*)data, …); }`) +
C-структуру-литерал (`static const struct C_тип _л_<экз> = { .поле = _трамп…};`);
`слушать` → `add_fn(объект, &_л_экз, (void*)&данные)`. Тела колбэков —
ОБЫЧНЫЕ функции с первым параметром `изменяемый T` (в C → `T*`, что и передаёт
трампулин) — **никакого `void*`/`небезопасно` у пользователя**. Тип-безопасность:
семантика сверяет тип `данные` == userdata-`T` на `слушать` (иначе каст неверен).
Инварианты целы: трампулин — прямой вызов (нулевая цена), `небезопасно` уходит в
доверенный сгенерированный код, borrow-checker не нужен. **Ловушка порядка
кодогена (закрыта):** пользовательские `#содержит` теперь печатаются ПОСЛЕ
Konda-типов (старый listener-паттерн `const Слушатель*` в C-заголовке ссылается
на Konda-структуру), но ДО прототипов/трампулинов (те ссылаются на C-тип из
заголовка — `struct wl_registry_listener`). **Фаза 2 (ВРЕМЯ ЖИЗНИ `данные`) —
отложена** (данные — обязательство пользователя; RAII-владение потом). Дальше
kfc распознаёт идиому и нацеливается на `слушать`. Тесты: `тип_слушатель`,
`тип_слушатель_бад`. Спецификация — `docs/ТИПИЗИРОВАННЫЕ_СЛУШАТЕЛИ.md`.

## §14. Интероп с C (одобрено 19.07, «с упором на статические проверки, минимум рантайма») — четыре конструкции, все с нулевой рантайм-ценой:

**Интероп с C (одобрено 19.07, «с упором на статические проверки, минимум
рантайма») — четыре конструкции, все с нулевой рантайм-ценой:**
(1) `внешняя` — прототип C-функции с `изменяемый`/`вывод`/`чтение`; кодоген
ставит `&` на вызове, C-декларацию даёт `#содержит`-заголовок (свой прототип
НЕ печатаем — конфликтовал бы со static inline); (2) `внешний тип Имя` —
непрозрачный C-тип, только через указатель (by-value — статическая ошибка;
представление: структура без полей с флагом `внешний`); (3) `чтение` —
const-ссылка (по_ссылке=3; не мутация: конст допустим, связи длины не рвутся).
**Обновлено (Задача 1 «безопасные указатели»): `чтение` теперь и у СВОИХ
функций**, не только `внешняя` — second-class const-reference, тело не может
писать в объект (иммутабельность через флаг `неизменяемый`, ловится проверкой
конст). Кодоген уже был генерическим (Тип* + `&` на вызове + `*` в теле),
снят лишь семантический гейт. Нулевая рантайм-цена: большие read-only
структуры без копии. `чтение` на примитиве — выбор программиста (для структур
быстрее, для примитива добавляет косвенность). Прежнее «своим функциям — по
значению» — теперь ОПЦИЯ, а не единственный путь; (4) **глобальные
`конст`** — строго иммутабельные константы верхнего уровня (примитивы-
константные выражения, `символ*`-строки, структуры-литералы с колбэками,
сигнатура колбэка сверяется с `типфункции`-полем, **и `конст`-массивы**
`конст T ИМЯ[N] = { … }` с элементом-примитивом, `символ*` ИЛИ **структурой**
(вложенные литералы полей/массивов разбираются рекурсивно
`разобрать_значение_инициализатора`; валидатор `конст_агрегат_ок`; чтение
`ТАБ[i].поле`/`ТАБ[i].поле[j]` с проверкой границ; заодно **поля-массивы
структур** `T поле[N]`, константный индекс) — таблицы charset/строк/вершин/
форматов; многомерность верхнего уровня отложена) → `static const` в C.
**Инвариант №4 цел**:
глобальных ПЕРЕМЕННЫХ нет, попытка — понятная ошибка и в парсере, и в семантике. Всё вместе закрывает wayland/GUI-паттерны
(out-параметры библиотек, opaque-хендлы, listener-структуры). Контекстные
слова: `внешняя`/`внешний`/`тип`/`чтение` — имена у программиста не отняты.

## §15. Батч-ошибки парсера — реализованы

**Батч-ошибки парсера — реализованы**: восстановление на границе объявления
верхнего уровня (следующая строка с колонки 1, начинающая объявление; предел
32), `разобрать_с_именами_структур_батч(...)`; CLI печатает все. AST после
восстановления годен только для диагностики (возвращается nullptr).

## §16. Обобщённые структуры — реализованы

**Обобщённые структуры — реализованы** (мономорфизация, тот же проход
`обобщения.c`, что и обобщённые функции). `структура Пара<T> { T первый … }`,
использование `Пара<целое32> п` в любой позиции типа (объявление/параметр/поле/
возврат). Каждый набор тип-аргументов → отдельный C-тип (`Пара_целое32`,
`Пара_символ_у`), нулевая рантайм-цена (инвариант №1). **Ключ архитектуры —
порядок фаз:** сперва мономорфизация функций (`подставить` заходит внутрь
`УЗЕЛ_ТИПОАРГУМЕНТ`, превращая `Пара<T>` в теле специализации в `Пара<целое32>`),
затем фаза структур обходит уже конкретные ссылки и порождает специализации
(свой ворклист — для транзитивных полей-структур). Парсер: `разобрать_тип_
аргументы_типа` после `съесть_именованный_тип`; `начинается_объявление_типа`
распознаёт `Имя<…>` как объявление только для известной обобщённой структуры
(иначе `п < x` — сравнение над переменной, чьё имя совпало с типом). **Scope
v1 (решение пользователя): поля — примитивы/указатели/другие структуры, НЕ
`срез<T>`** (отдельная итерация, чтобы обобщения не пересекались с autofree/
деструкцией; `срез<T>`-поле отвергается парсером). Ошибка Konda: арность
тип-аргументов структуры (с позицией). Тесты: `обобщённая_структура`,
`обобщённая_структура_функция`, `обобщённая_структура_арность`.

## §17. Вывод тип-аргументов — реализован

**Вывод тип-аргументов — реализован** (`макс(1,2)` ≡ `макс<целое32>(1,2)`).
**Архитектура — ГИБРИД (решение пользователя):** отдельный проход семантики
`вывести_типоаргументы` в `режим_вывода` типизирует аргументы обобщённых
вызовов ТЕМ ЖЕ `типизировать_выражение` и дописывает выведенные
`УЗЕЛ_ТИПОАРГУМЕНТ` ДО мономорфизации; настоящая семантика затем валидирует
специализацию как обычно. **Охват v1 (решение пользователя): вывод ТОЛЬКО из
конкретных аргументов**; если тип аргумента сам зависит от неразвёрнутого
обобщения (поле/переменная обобщённо-структурного типа) — нужны явные `<>`
(полный «инстанциация при тайп-чеке» отвергнут как крупная перестройка с
риском для IDE-API). **Три закрытых подводных камня двойного прогона семантики
(детали — `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md` §обобщения):** (1) кодоген-
подсказки (`проверка_бинопа`/`безопасный_индекс`/`проверка_аргументов`) не
пишем в `режим_вывода` — иначе ложная подсказка переживает до кодогена;
(2) `подготовить_оператор` мутирует токен (не идемпотентен) → оператор-функции
в проходе вывода пропускаем; (3) `подставить` теперь копирует имя типа ГЛУБОКО
(`strndup`) — иначе выведенное имя-аргумент повисало бы после освобождения.
Невыводимый вызов без `<>` → понятная ошибка «укажите явно». Тесты:
`вывод_типоаргументов`, `вывод_смешанный`, `вывод_невозможен`.

## §18. Cross-file generics — реализованы

**Cross-file generics — реализованы.** Сам разворот шаблонов уже был
cross-file: `слить_программы` объединяет файлы в одно дерево ДО мономорфизации,
так что `мономорфизировать`/`вывести_типоаргументы` видят все шаблоны и вызовы.
Единственный пробел был в ПАРСЕРЕ: пред-скан имён обобщённых
(`собрать_типопараметры`) — пер-файловый, поэтому парсер файла-потребителя не
знал, что `макс`/`Пара` из соседнего файла — обобщённые, и трактовал `<` как
сравнение. Решено по образцу `собрать_имена_структур`: новый набор
`ИменаОбобщённых` (`собрать_имена_обобщённых` — паттерн «ИМЯ<» на глубине
фигурных = 0, по всем файлам), передаётся в
`разобрать_с_именами_структур_обобщённых_батч` (старый `…_батч` — обёртка с
nullptr, сигнатура не сломана; IDE — однофайловый, ему хватает пер-файлового
пред-скана), сидируется в `р.обобщённые` до `собрать_типопараметры`. Порядок
файлов не важен (сбор имён — до разбора). Тесты: `обобщ_главный`/`обобщ_модуль`
(обе перестановки). **Все три обобщённые фичи (структуры, вывод, cross-file) —
готовы.**

## §19. `goto` — НЕ реализовывать

**`goto` — НЕ реализовывать** (сознательное решение). Конфликтует с ядром
инвариантов Konda: definite-assignment (прыжок через инициализацию → чтение
мусора), владение/деструкторы/autofree (прыжок из/в область минует
RAII-деструкцию → утечка/double-free), move/borrow-анализ. Все текущие анализы
**структурные** (по дереву if/while/for); безопасный `goto` потребовал бы
CFG-анализа с потоками по произвольным рёбрам — крупная перестройка, высокий
риск. Главный use-case («goto cleanup») в Konda **уже не нужен**: срезы
autofree сами освобождаются при выходе из области. Безопасная альтернатива для
выхода из вложенных циклов (помеченные `прервать`/`продолжить`) — возможна
позже как отдельная структурная фича, но не `goto`.

## §20. Оптимизации `Срез`/`выделить` (A/B/C) — реализованы

**Оптимизации `Срез`/`выделить` (A/B/C) — реализованы** (по запросу
пользователя, все нулевой рантайм-цены, безопасность неизменна). Детали —
`docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md` §«Этап B/E» и README §срезы.
**(A) Дескриптор `Срез` — 16 байт** (`{данные, длина}`, без `эл_размер`):
размер элемента известен статически, кодоген передаёт `sizeof(T)` литералом в
`срез_доступ`/`срез_выделить`/`срез_клон` (как `массив_доступ`). Дешевле
копировать/двигать, умножение индекса — на компайл-тайм-константу. **Ломает ABI
готовых `.so` пути-2** → регенерировать `.h`. **(B) Элизия знак-клампа**
`количество < 0 ? 0` в `выделить`: вариант `срез_выделить_бз` берётся, когда
количество доказанно ≥ 0 (беззнаковый тип или числовой литерал; семантика
проставляет знаковость на узел количества). `calloc` всё равно ловит
переполнение размера. **(C) Стековое размещение срезов** (escape-анализ
`собрать_стек_срезы`/`срез_не_убегает` в `кодоген.c`): `срез<T> с =
выделить(литерал)` с `N·sizeof ≤ 4096`, не покидающий область (не
возвращается/не move/не переприсваивается), → `T _стек_с[N] = {0}` вместо
`calloc`/`free`. Надёжно по построению (нет сырого `&`/глобалов → срез
неалиасим → обход по имени полон; нераспознанное использование → консервативно
куча). Ложное продвижение = use-after-return/double-free, поэтому по умолчанию
куча; покрыто ASan и negative-тестами. **D (элизия зануления malloc-вместо-
calloc) — сознательно НЕ делали** (высокий риск, выигрыш мал: ядро отдаёт
нулевые страницы).

## §21. Ссылки на проекции — реализованы

**Ссылки на проекции — реализованы** (`ф(изменяемый т.х)`, `ф(вывод с[и])`,
`ф(изменяемый м[1])`, цепочки `т.а.б`; и для `чтение` у `внешняя`). Итог
анализа «частично безопасных указателей»: модель — **second-class reference**
(Hylo/Val), расширение ровно на одно измерение без borrow-checker. Безопасно
по построению: база в кадре вызывающего заморожена на время вызова; нет
сырого `&`/глобалов/замыканий → ссылке некуда утечь; границы среза — **при
формировании ссылки** (тот же `срез_доступ`, BCE под охранником работает и
тут). Статически отвергнуты: временное (`функция()[и]`), проекция `конст`,
поле-срез (дескриптор владеет памятью), `владеет`-move того же среза в том же
вызове (обратный порядок ловит обычный use-after-move). Кодоген не менялся
(`&` + существующая эмиссия lvalue); `собрать_изменяемые` расширять не
нужно — мутируется содержимое, не переменные (урок 17.07 цел). Дальше НЕ
идти: первоклассный `&` = времена жизни = borrow-checker (отвергнут).
Детали — `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md` §6.5; тесты `реф_*`.

## §22. Типы элемента среза (`срез<структура>`, `срез<T*>`) — реализованы

**Типы элемента среза (`срез<структура>`, `срез<T*>`) — реализованы** (Задачи
2+4 плана безопасных указателей, `docs/ПЛАН_БЕЗОПАСНЫХ_УКАЗАТЕЛЕЙ.md`). Раньше
элемент среза мог быть только примитивом; теперь — ИМЕНОВАННАЯ структура (по
значению: `срез<Точка>`, доступ `с[i].поле`, `для_каждого`) или указатель
(`срез<символ*>` — слайс строк, `срез<Точка*>`). Та же срез-машинерия (границы,
autofree дескриптора, move/клон); **нулевая рантайм-цена** (инвариант №1).
**Вертикальный срез по 4 файлам:** парсер `съесть_тип_` (именованный элемент +
суффикс `*`, `узел->указатели` = косвенность ЭЛЕМЕНТА); семантика (ветку
объявления структуры гейтим `&& !узел->срез`; символ несёт `индекс_структуры`
элемента; `совместимы_для_присваивания` для срезов сверяет
`указатели`+`индекс_структуры` → `срез<A>≠срез<Б>`, `срез<T>≠срез<T*>`); кодоген
`эмит_тип_элемента` (имя структуры + `*`, не `тип_токена_в_си`→«int»). **Ключ —
лайфтайм имени:** анализатор освобождается ДО кодогена, поэтому
`ОписаниеСтруктуры.имя_токен` указывает В ИСХОДНИК (переживает) — по индексу
восстанавливаем имя типа для каста. **Autofree-гейт (Задача 7 не сделана):**
`срез<структура-с-владеющими-полями>` (срез/деструктор) → ошибка — срез НЕ
вызывает деструкторы элементов (транзитивная деструкция), была бы утечка/
double-free; `срез<структура*>` разрешён (указатели заимствуются, деструкции
нет). Тесты: `срез_структура`, `срез_указателей`, `срез_структура_владеющая`,
`срез_структура_несовместимость` (+ ASan/UBSan). Дальше по плану — Задача 5
(`Ящик<T>` = `срез<T>` длины 1) на этом же каркасе.

## §23. `Ящик<T>` — одиночный владеющий heap-объект (Задача 5) — реализован

**`Ящик<T>` — одиночный владеющий heap-объект (Задача 5) — реализован.**
Аналог Rust `Box`: `Ящик<T> б = выделить()` (без арг) → `T* б = calloc(1,
sizeof(T))`, `б.поле` = `б->поле` (авто-разыменование), autofree `free(б)` при
выходе, move `Ящик<T> в = б` (источник перемещён, двойного free нет).
**Реализация — владеющий ненулевой указатель + флаг `ящик`** (НЕ дескриптор):
парсер даёт `Ящик<T>` = указатель на T (`указ_эл++`) + `узел->ящик`; семантика
ведёт box ДО веток структуры/среза (символ `ящик`+`владеет_срезом` для
autofree, `может_быть_нуль=0`, move через ту же машинерию, что срез); кодоген
`кодоген_объявления_ящика` + `зарегистрировать_ящик_к` (release = `free(б)`, не
`free(б.данные)`). **Ключевой приём — переиспользование:** доступ к полю
(`указатели==1`→`->`) и эмиссия типа `T*` уже были — новое только конструктор/
autofree/move. `ИнфоТипа` НЕ расширяли (box в выражении = обычный `T*`; владение
на Символе) → 0 предупреждений. **Scope v1:** T — структура **без владеющих
полей** (иначе транзитивная деструкция Задача 7 → ошибка); примитивы-содержимое,
фабрики-возврат `Ящик<T>` и `владеет Ящик<T>`-параметры отложены. Нулевая
доп. цена. Тесты `ящик`/`ящик_uam`/`ящик_влад`/`ящик_арг` (+ASan). Закрывает
weston-идиому `zalloc(sizeof *x)` (одиночная heap-структура).

## §24. Аллокатор `--аллокатор=jemalloc|libc` — реализован (дефолт jemalloc)

**Аллокатор `--аллокатор=jemalloc|libc` — реализован (дефолт jemalloc).**
Реализация проще плана с швом: **интерпозиция линковкой**, без изменения
кодогена. jemalloc → в argv компилятора добавляется `-l:libjemalloc.so.2`
(версионный soname — работает и без dev-пакета, только с рантайм-либой); он
ставится ПОСЛЕ источника, поэтому неопределённые `calloc`/`free` программы
разрешаются в jemalloc, а не libc. `libc` → ничего не линкуем. Всё в
единственной точке вызова компилятора `скомпилировать_си` ([ввод_вывод.c]).
**Только для исполняемых файлов**: у `--библиотека` (`.so`) jemalloc НЕ
навязывается — аллокатор выбирает финальная программа. **На кроссе**
(`--целевая-архитектура`) без явного `--аллокатор` — авто-`libc` (host-
jemalloc в target-sysroot нет). Семантика `calloc` (зануление + overflow-
check) не тронута — интерпозиция её сохраняет. **ASan-сборка — только libc**
(jemalloc конфликтует с интерцепторами; ASan-прогоны в тестах компилируют
сгенерированный C напрямую `cc`, минуя эту точку). Фаза 2 (если понадобится) —
sized-free через `sdallocx`, но она требует шва в прологе (у `Срез` размер
уже есть); пока не нужна.

## §25. Кросс-компиляция `--целевая-архитектура=<триплет>` — реализована (пока только gcc)

**Кросс-компиляция `--целевая-архитектура=<триплет>` — реализована (пока
только gcc).** Генерируемый C уже переносим (типы через `stdint`, нет
инлайн-ассемблера/интринсиков), поэтому кросс — это выбор компилятора в
единственной точке `скомпилировать_си`, а не переработка кодогена. Триплет →
компилятор `<триплет>-gcc` (напр. `aarch64-linux-gnu-gcc`; `execvp` ищет по
PATH — command injection не появляется, argv по-прежнему массив). Без триплета
— обычный `cc`. **Не сделано (осознанно, v1):** clang (`--target=`+`--sysroot=`);
библиотеки пути-2 должны быть пред-собраны под цель (их `.so`/rpath — хостовые);
мелкий host-`sizeof(void*)` в пороге стекового размещения срезов
([кодоген.c] `размер_элемента_байт`) — влияет лишь на эвристику продвижения,
не на корректность.

## §26. `--только-си` (`--only-c`) — реализован

**`--только-си` (`--only-c`) — реализован.** Выдаёт `.c` (и `.h`/`.и` для
библиотеки) и пропускает вызов компилятора. Удобно для инспекции кодогена и
ручной сборки/кросса чужим тулчейном.

## §27. Бэктрейс при аварии — реализован (решение пользователя)

**Бэктрейс при аварии — реализован (решение пользователя).** Любой guard
(границы среза/массива/`аргументы`, деление на ноль, переполнение) перед
`abort` зовёт `[[noreturn]] конда_прервать` (`ПРОЛОГ_ПАНИКИ` в `кодоген.c`):
`backtrace()` + `backtrace_symbols_fd(2)` (без `malloc`) + `abort`. **Бэктрейс
ВСЕГДА** (и отладка, и релиз). **Цена на горячем пути — ноль:** печать только
на пути отказа, один раз, перед `abort`; ложится в инвариант №1 без исключений.
Явные решения пользователя по флагам: **(1) `-fno-omit-frame-pointer` НЕ
добавлять** (стоил бы регистра/скорости в релизе; раскрутка идёт по DWARF
`.eh_frame` — frame pointer не нужен); **(2) размер-влияющие флаги
(`-rdynamic`/`-funwind-tables`/`-g`) — по умолчанию ВКЛ** (влияют только на
размер бинарника, не на скорость), снимаются `--без-символов` (`--no-symbols`)
→ бэктрейс остаётся, но кадрами-адресами; полная символикация — `addr2line`.
Параметр `символы` у `скомпилировать_си`. `execinfo.h` — под
`#if defined(__GLIBC__)`, иначе деградация до `abort` (переносимость кросса).

## §28. Hardening-флаги компилятора (Tier 2, решение пользователя) — добавлены

**Hardening-флаги компилятора (Tier 2, решение пользователя) — добавлены.**
В `скомпилировать_си` ([ввод_вывод.c]) для ВСЕХ выходов (отладка/релиз/
библиотека) ставятся пять флагов с **нулевой ценой на горячем пути** (инвариант
№1 цел): `-Wl,-z,relro -Wl,-z,now` (full RELRO — GOT только-чтение после
старта), `-Wl,-z,noexecstack` (NX-стек), `-fstack-clash-protection`
(зондирование крупных кадров — не даёт аллокации ПЕРЕПРЫГНУТЬ guard-страницу,
прямо усиливает защиту стека из рекурсии: обработчик ловит постфактум, а этот
флаг предотвращает перепрыг вовсе), `-fstack-protector-strong` (канарейка
против переполнения буфера в кадре). **Зачем явно, если хост-gcc это дефолт:**
кросс-тулчейны / vanilla clang / musl могут НЕ включать → задаём явно как
переносимую страховку на цель. Проверено `readelf`: `GNU_RELRO`+`BIND_NOW`,
`GNU_STACK RW` (не RWX), `__stack_chk_fail`. **НЕ добавляли:** `-march=native`
(ломает переносимость/кросс), явный PIE (уже дефолт линковки), `-flto`
(выигрыш мал — обычно один слитый `.c`, а линковку путь-2 `.so` усложняет).
**Рассмотрены и отложены пользователем:** `-fno-strict-aliasing` (Tier 1 —
латентный мискомпил реинтерпретации указателя под `-O2`, сиблинг принятого
`-fwrapv`) и `-D_FORTIFY_SOURCE=2` (Tier 3 — крошечный ненулевой рантайм,
формально против инварианта №1). Тест: `флаги_сборки` грепает наличие всех
пяти в команде компиляции (отладка и релиз). На sweep-фазы санитайзеров НЕ
влияет — те зовут `cc -fsanitize` напрямую, минуя `скомпилировать_си`.

## §29. Безопасность рекурсии — реализована (три хода, все нулевой рантайм-цены)

**Безопасность рекурсии — реализована (три хода, все нулевой рантайм-цены).**
Была последняя дыра memory-safety: глубокая рекурсия → переполнение стека →
сырой SIGSEGV, а при большом кадре — перепрыг guard-страницы и порча чужой
памяти (UB). Закрыто без единой инструкции на горячем пути (инвариант №1):
**(1) Защита стека** — обработчик SIGSEGV на АЛЬТ-стеке (`sigaltstack`+
`SA_ONSTACK`, ставится `__attribute__((constructor))` у любого исполняемого
файла — `программа_имеет_main`). Само переполнение ловит АППАРАТНАЯ
guard-страница (0 инструкций); обработчик лишь превращает недетерминированный
сбой в чистую панику `конда_прервать` (бэктрейс+abort). Отличает переполнение
от прочего SIGSEGV по `si_addr` в `[верх−RLIMIT_STACK, верх]` (вершина
захвачена в конструкторе; без завязки на pthread). Прочий SIGSEGV (в safe-коде
не бывает; только в `небезопасно`) → дефолт (штатный core). `ПРОЛОГ_ЗАЩИТЫ_
СТЕКА` под `#if defined(__GLIBC__)`. **Ограничение v1:** точны границы ГЛАВНОГО
потока; переполнение в pthread-потоке падает дефолтным SIGSEGV — тоже
безопасно (guard-страница, порчи нет), но без Konda-бэктрейса. Ставит панику у
ВСЕХ исполняемых → `ПРОЛОГ_ПАНИКИ` теперь эмитится всегда (тест
`явный_возврат` перешёл с `grep -c return` на `return 7`/нет `return 0`, т.к.
`[[noreturn]]` в прологе содержит «return»). **(2) Гарантированный TCO** —
хвостовая САМО-рекурсия `вернуть сам(...)` помечается `КОНДА_ХВОСТ`
(`[[clang::musttail]]`/`[[gnu::musttail]]`, gcc ≥ 15) → компилятор ОБЯЗАН
сделать переход (или ошибка) → переполнения нет ПО ПОСТРОЕНИЮ, даже в отладке
(-O0). Макрос при неподдержке ПУСТ → обычный вызов (корректность цела).
Гейты airtight (кодоген никогда не упрётся в ошибку musttail): только вызов
той же функции (сравнение текстов токенов — после мономорфизации несут
манглированное имя, поэтому вызов ДРУГОЙ специализации не совпадёт), нет
живых владеющих (autofree не теряется), нет ref/out/`чтение`-параметров, не
main, возврат — примитив/указатель. **(3) Предупреждение** о нехвостовой
прямой/взаимной рекурсии — ТОЛЬКО по флагу `--предупреждать-рекурсию`
(`--warn-recursion`), по умолчанию МОЛЧИТ (иначе шумело бы на всей
легитимной рекурсии). Отдельный проход `предупредить_о_нехвостовой_рекурсии`
([семантика.c], зовётся из CLI после анализа — сигнатуры и IDE-API не тронуты):
граф вызовов + транзитивное замыкание (Уоршелл, ≤ 1024 функций, иначе только
прямая) → взаимная рекурсия предупреждается всегда, прямая — только если не все
само-вызовы хвостовые (или функция непригодна к TCO). Тесты:
`стек_переполнение` (SIGABRT+«переполнение стека», не segfault),
`хвостовой_tco` (10 млн уровней в -O0 не падают), `нехвостовой_нет_tco`
(нет `КОНДА_ХВОСТ return`), `рекурсия_предупр` (флаг вкл/выкл). **Под ASan**
фикстура-переполнение даёт SIGSEGV без маркера санитайзера (ASan перехватывает
наш обработчик) → корпусная фаза .elf её пропускает штатно. **Требование
gcc ≥ 15 или clang ≥ 19:** musttail (→
ГАРАНТИРОВАННЫЙ TCO) у gcc есть только с 15-й версии; полный C23 (-std=gnu23,
nullptr) требует clang ≥ 19. Старый компилятор собрал бы БЕЗ гарантии —
рантайм-часть `хвостовой_tco` (10 млн уровней в -O0) тогда переполнила бы стек
(кодоген корректен, защита стека чисто перехватывает, но это не гарантия).
Поэтому старый компилятор — **ЯВНАЯ ОШИБКА**: и в `Makefile` (`$(error)` при
`-dumpversion` < 15 для gcc / < 19 для clang), и в `tests/run.sh`
(`fail` при gcc < 15 / clang < 19). CI (`.github/workflows/c-cpp.yml`)
ставит gcc-15 из toolchain-PPA и делает `cc`/`gcc` ссылкой на него — важно,
что транспилятор компилирует вывод ВНУТРЕННИМ `cc`, не только `make`, поэтому
оба должны быть gcc-15. Раз gcc ≥ 15 гарантирован, `хвостовой_tco` ассертит
завершение БЕЗУСЛОВНО (грепа `КОНДА_ХВОСТ return` это не касается — токен
кодоген эмитит всегда).


## §30. Кастомный аллокатор — пер-тип, внешняя память, autofree-хук (v1: Ящик<T>)

**Кастомный аллокатор — реализован (v1: `Ящик<T>`).** Решение пользователя по трём
развилкам (AskUserQuestion): (1) форма — **пер-тип** (аллокатор привязан к
конкретному владеющему типу, а не глобально); (2) состояние пула (арена/free-list)
— во **внешней памяти** (`внешняя` C: mmap/sbrk/статический C-буфер), чтобы
инвариант №4 остался цел (изменяемое состояние живёт в C/OS, названо через
интероп, как весь C-интероп) — глобальных изменяемых Konda-переменных фича не
вводит; (3) автоудаление — **через хук**: RAII-autofree сохраняется, но зовёт
`освободить` аллокатора вместо `free` (гарантии «нет утечек/double-free» целы).

**Синтаксис.** Объявление — контекстное слово `аллокатор` (имя не отнимается):
```
аллокатор Имя { выделить = функция_alloc  освободить = функция_free }
```
где `выделить`/`освободить` — обычные функции (обычно `внешняя` C: `целое8*
alloc(целое64)` и `ничего free(целое8*)`). Привязка к типу — контекстное `в`:
`Ящик<T> в Имя б = выделить()` и `срез<T> в Имя с = выделить(N)`.

**Обновление: срез поддержан (пункт 1 «универсального» роадмапа).** `срез<T> в Имя`
работает так же, как обычный срез (владение, autofree, move, клон, проверка
границ **сохраняется**), но выделение/клон идут через сгенерированные пер-аллокатор
помощники `_срезвыд_<Имя>`/`_срезклон_<Имя>` (эмитятся после `#содержит`+прототипов;
внутри — guard переполнения `N*sizeof`, проверка неудачи аллокации, `memset` =
паритет с `calloc`), а autofree зовёт освободитель. Стек-элизия для кастомного
среза отключена (память обязана прийти из аллокатора). Cross-boundary передача
владения запрещена в v1 (аннотация аллокатора не переносится через сигнатуру):
**возврат** кастомного среза из функции, передача в **`владеет`-параметр**,
инициализация **вызовом функции**, **переприсваивание** — ошибки компиляции;
заимствование (обычный срез-параметр, `длина`, индекс, `для_каждого`, `клон` как
источник) — по-прежнему можно. Move — только между тем же аллокатором (равенство
имён).

**Кодоген (нулевая цена, инвариант №1).** `Ящик<T> в Имя б = выделить()` →
`T* б = (T*)alloc(sizeof(T)); memset(б, 0, sizeof(T));` (зануление — паритет с
`calloc`: свежий Ящик читается нулями). Autofree на выходе из области →
`free((void*)б)` вместо `free(б)`. Прямые вызовы — ни диспетчеризации, ни
рантайм-стоимости. Таблица аллокаторов (`алл_имя/алл_выделить/алл_освободить`) в
`Кодоген`; функция-освободитель хранится на записи стека владеющих
(`освободить_владеющего[]`), поэтому autofree/move печатают верный вызов.

**Безопасность.** Аллокатор — часть идентичности типа: move `Ящик<T> в А ← Ящик<T>
в Б` — **ошибка** (иначе autofree получателя освободил бы память НЕ тем
аллокатором → порча); проверяется в семантике равенством имён аллокатора
источника и получателя. Возврат Ящика уже отвергнут в общем (владеющий heap не
`безопасен_для_возврата`), `владеет`-параметры — только для срезов, поэтому
единственный move-путь Ящика — локальная инициализация, и он закрыт проверкой
равенства. Неизвестный аллокатор в `в Имя` — ошибка с подсказкой.

**Ограничения v1 (осознанные, не дыры).** `Ящик<T>` и `срез<T>` поддержаны;
cross-boundary передача владения кастомно-аллоцированного значения (возврат,
`владеет`-параметр, приём от функции) запрещена — аннотация аллокатора не
переносится через сигнатуру функции. Тело `выделить`/`освободить` обычно
`внешняя` C (Konda не возвращает сырой указатель вне `небезопасно`). Тесты:
`аллокатор_ящик`/`аллокатор_срез` (выделение через кастом + memset + autofree-хук,
работают под ASan), `аллокатор_срез_границы` (проверка границ цела),
`аллокатор_move`/`аллокатор_срез_move` (move — освобождение ровно один раз),
негативы `аллокатор_неизв`/`аллокатор_разные`/`аллокатор_срез_cross`/
`аллокатор_срез_возврат`/`аллокатор_срез_владеет`/`аллокатор_срез_пере`.

## §31. Символьные литералы «'x'» — реализованы (решение пользователя)

Мотивация: конвертер `konda-from-clang` на реальном C (`if (entry->d_name[0] ==
'.')`) упирался в отсутствие символьных литералов В САМОМ ЯЗЫКЕ — конвертер честно
эмитил `'.'`, но транспилятор его не парсил. Пользователь выбрал: делать
литералы в языке (а не обходной путь «'.'→46» в конвертере).

Оказалось, что **лексер уже** собирал `'…'` в `ТОКЕН_СИМВОЛ` (с обработкой
escape, зеркально строкам) — не хватало лишь пути парсер→семантика→кодоген.

Реализация (полный вертикальный срез, один коммит):
- **AST**: узел `УЗЕЛ_СИМВОЛ` (токен — литерал вместе с кавычками).
- **Парсер** (`разбор.c`): `ТОКЕН_СИМВОЛ` → `УЗЕЛ_СИМВОЛ` в primary-выражении
  (зеркально `ТОКЕН_СТРОКА`).
- **Семантика** (`семантика.c`): тип — **скаляр `символ`** (`char`), НЕ `int`
  (в отличие от C, где char-литерал имеет тип int; в Konda тип — `символ`, что
  естественнее для сравнений `символ == 'x'`). Проверка завершённости: пустой
  `''` или незакрытый (лексер обрывает на переводе строки) → ошибка Konda с
  позицией. Литерал — «безопасен для возврата» (значение, не адрес).
- **Кодоген** (`кодоген.c`): токен уже `'x'` (кавычки + escape) — валидный
  C-символьный литерал, эмитируется **дословно** (как строки). Escape
  (`'\n'`, `'\0'`, `'\''`, `'\\'`) проходят как есть — C понимает те же.

Границы v1: рассчитано на ASCII-литералы (частый случай — разбор байтов/текста).
Не-ASCII многобайтовый `'ф'` эмитится дословно → в C это multi-char литерал
(предупреждение, implementation-defined) — осознанный компромисс, отдельная
поддержка широких символов не делалась (нужды нет).

Тесты: `символьный_литерал` (`'.'`/`'\n'`/`'\0'`, сравнение, рантайм-вывод
«точка перевод нуль»), негатив `символ_пустой` (`''` → ошибка). Прогнан весь
корпус под ASan+UBSan (обе оси) — чисто.

Осталось за кадром (НЕ блокирует символьные литералы): `g.c` пользователя после
этого фикса упирается в ТРЕТИЙ, отдельный барьер — инициализация `возможно<DIR*>`
результатом `opendir` (интероп внешнего opaque-типа), не связанный с литералами.

## §32. Мини-stdlib для файлового ввода/вывода — реализована (v1)

**Задача.** Показать, что «безопасно вызывать syscalls» на Konda **возможно и
удобно**, и заложить каркас стандартной библиотеки, повторяющей идиому Rust `std`
на слое интеропа с C: единственная точка `небезопасно` — в тонком C-шиме, а
пользователь работает с типами.

**Архитектура — три слоя.**
- **L0** — POSIX (`open`/`read`/`write`/`close`/`fstat`). Скрыт от пользователя.
- **L1** — `stdlib/конда_ио.h`. Тонкие `static inline` функции. Принимают fd и
  Konda-`Срез` **по значению** (`{данные, длина}`) → границы гарантируются длиной
  среза ПО ПОСТРОЕНИЮ; `read`/`write` не могут выйти за буфер. Возврат — `long`:
  `≥0` = байты/fd, `<0` = `-errno` (signed сам служит маркером ошибки; не нужен
  out-параметр и `<errno.h>` в пользовательском коде). Три отдельные `open` по
  режимам (`_чтение`/`_запись`/`_добавление`) — так POSIX-флаги ВООБЩЕ не
  пересекают границу Konda. Единственная зона «доверия» — аудируется один раз.
- **L2** — `stdlib/файл.конда`. Безопасные Konda-обёртки: `Файл` с
  `[удалить = _файл_закрыть]` (**RAII**, авто-close при выходе из любой области,
  включая ветку `выбор`); sum-типы `Открытие { Открыт(целое32 фд)  Ошибка(целое32
  код) }` и `ИтогИО { Байт(целое64)  Сбой(целое32) }` — компилятор ЗАСТАВЛЯЕТ
  обработать оба случая (неисчерпывающий `выбор` — ошибка). Публичный API:
  `открыть_чтение / открыть_запись / открыть_добавление / прочитать / записать /
  размер`.

**Гарантии, которые язык обеспечивает бесплатно.** Пользовательский код (пример
`stdlib/пример_файл.конда`) НЕ содержит ни одного `небезопасно`, ни одного сырого
указателя, ни ручного `close`. При этом: (а) RAII закрывает fd на всех путях
выхода (включая ранний `вернуть` из ветки `выбор`); (б) read не выйдет за длину
среза; (в) errno не глобал — код ошибки в варианте sum-типа; (г) забыть ветку
ошибки нельзя — не скомпилируется. Проверено под ASan+UBSan+LSan — **ноль
утечек, ноль UB**. Стоимость обёрток — прямые вызовы `static inline` в шиме;
runtime overhead **нулевой** сверх самих syscalls (инвариант №1 цел).

**Ограничения v1 (осознанные, планируется снять).**
1. Sum-варианты **не принимают поле-структуру с деструктором** (текущий предел
   реализации sum-типов) → `Открыт` несёт `целое32 фд`, а RAII-`Файл` создаётся
   вручную в ветке (`Файл ф = { фд = фд }`). Приемлемо, идиома видна.
2. Нет обобщённого `Результат<T,E>` (нет обобщённых sum-типов в языке) → на
   каждую операцию свой sum-тип (`Открытие`/`ИтогИО`). Когда обобщённые sum
   появятся — унифицируем в единый `Результат<T,Ошибка>`.
3. **Пути к заголовку шима** резолвятся через `-I <каталог исходника>`, поэтому
   пользовательский `.конда` пишет `#содержит "конда_ио.h"` и должен лежать
   в одном каталоге с шимом ИЛИ передавать шим первым файлом. «Прелюдия»
   (автоподключение stdlib из CLI) — следующий пункт роадмапа.

**Пункт роадмапа «универсальность языка».** Именно этот приём — «Срез по
значению в C-шим + RAII-структура + sum-тип ошибки» — доказывает, что вокруг
любой POSIX-API строится безопасный слой БЕЗ языковых расширений: сокеты,
процессы, mmap делаются по тому же шаблону.

Тесты: `run.sh` собирает `stdlib/файл.конда`+`stdlib/пример_файл.конда`, проверяет
запуск, наличие RAII-хука в кодогене; корпусной ASan подтверждает чистоту.

## §33. Обобщённые sum-типы («перечисление Результат<T, E> {…}») — v1 реализованы

**Задача.** Ввести обобщённые размеченные объединения (`Результат<T,E>`,
`Опция<T>` и пр.) — фундамент выразительной обработки ошибок и опциональных
значений. Без них stdlib вынуждена плодить не-обобщённые sum-типы на каждую
операцию (`Открытие`, `ИтогИО`, …), что нарушает DRY.

**Реализация — параллельна обобщённым структурам** (§16). `обобщения.c`
получил третью таблицу `enum_шаблоны` рядом с существующими `шаблоны`
(функции) и `структ_шаблоны` (структуры); сбор — по ведущим
`УЗЕЛ_ТИПОПАРАМЕТР` (тот же критерий, что для структур). Мономорфизация:
1. фазы 1–3б без изменений (функции, структуры);
2. **фаза 3в** — обход дерева в поиске ссылок вида `Р<X,Y>` в позиции
   типа. Для каждой — клонирование шаблона, `подставить()` тип-аргументы,
   `удалить_детей_типа(УЗЕЛ_ТИПОПАРАМЕТР)`, `переименовать()` в
   `Р_<суффикс>` (тот же алгоритм, что у структур);
3. фаза 4 — специализации перечислений идут в перестроенном дереве
   **перед** структурами (сумма может быть полем структуры).

Парсер (`разбор.c` — `разобрать_перечисление`) теперь принимает `<T, U>`
после имени, добавляя ведущих детей `УЗЕЛ_ТИПОПАРАМЕТР` — по той же схеме,
что уже была для структур. Cross-file собран автоматически: пред-проход
`собрать_имена_обобщённых` собирает **любой** идентификатор перед `<` на
глубине скобок 0 — перечисления подхватились без правок сбора.

**Ограничение v1 (сознательное).** Имена вариантов внутри
специализированного enum-типа **не манглируются** (Конструктор `Успех`
остаётся `Успех`, а не `Успех_Результат_целое32_целое32`). Значит если бы в
одной программе появилось две специализации того же шаблона
(`Результат<целое32,E>` и `Результат<символ*,E>`), обе имели бы `Успех` —
конструктор `Успех(5)` без вывода типа-контекста стал бы неоднозначным. Пока
проход вывода типа-контекста не написан, **обобщения.c даёт понятную ошибку
компиляции** при попытке второй специализации: «уже специализировано иначе;
v1 поддерживает одну специализацию на шаблон». Обходной путь: единый набор
тип-аргументов на всё приложение (типичный случай — `Результат<T, Ошибка>`
с фиксированной `Ошибка`), либо не-обобщённые перечисления.

**stdlib/файл переписан на единый `Результат<целое64, целое32>`.** Раньше
модуль объявлял два не-обобщённых sum-типа (`Открытие`, `ИтогИО`) — теперь
один. `T=целое64` покрывает и fd, и число байт; `E=целое32` — errno.
Пользователь пишет универсально:
```konda
выбор открыть_чтение(путь) {
    Успех(фд64) { Файл ф = { фд = как<целое32>(фд64) }  … }
    Провал(код) { printf("не удалось: %d\n", код) }
}
```

**Кодоген — без изменений.** Мономорфизация выдаёт обычные не-обобщённые
`УЗЕЛ_ПЕРЕЧИСЛЕНИЕ`-узлы с манглированным именем; `кодоген_sum_перечисления`
эмитит `typedef struct { тег; union {…} } Результат_целое32_целое32`; тег
варианта резолвится через существующий `найти_sum_вариант_к`. **Нулевая
рантайм-цена** (инвариант №1 цел): один бранч по тегу, без исключений/кучи.

Тесты (`run.sh`):
`обобщ_сум_базовый` (мономорфизация, ветка Успех, имя `Результат_целое32_
целое32`), `обобщ_сум_провал` (ветка Б, отрицательный аргумент), `обобщ_сум_
дубль` (guard v1: две специализации того же шаблона → ошибка), `обобщ_сум_
арность` (неверное число тип-аргументов); + stdlib-пример с `Результат<целое64,
целое32>` покрывает end-to-end на реальном IO. Полная сюита + ASan-корпус —
зелёные, регрессий нет.

**Дальше.** Устранение v1-ограничения: (а) вывод типа-контекста при вызове
конструктора варианта (Rust-style: LHS-тип определяет специализацию), либо
(б) манглинг имён вариантов в специализации с автоматической перепиской
пользовательских конструкторов. Оба пути значительны и заслуживают отдельного
решения — не тянутся в v1.

## §34. Именованные типы через «.и»: структуры и sum-перечисления (v2 пути 2)

**Задача.** В §5 интерфейс `.и` нёс только функции (примитивы, `срез`,
указатели); структуры и sum-перечисления через границу библиотеки были
непрозрачны (fallback к `.h`). Без этого stdlib-модули вроде `файл` не могли
экспортировать `Файл` (RAII-хендл с деструктором) и `Результат<…>` — ключевые
типы их API.

**Решение.** `.и` дополнен объявлениями типов: `С Имя дестр` + `Поле` + `КС`
(структура), `Е Имя` + `Вар`/`ВП` + `КЕ` (sum-перечисление); параметры/возврат
именованного типа — `П структура … Имя`/`В перечисление … Имя`. Потребитель
**реконструирует** типы как полноценные узлы AST (флаг `из_библиотеки`), они
проходят штатные `собрать_структуры`/`собрать_перечисления`, а C-определения
приходят из `.h` (typedef не эмитится заново — нулевая дубликация).

Инвариант не нарушен: **проверки остаются статическими**, нулевая рантайм-цена;
деструктор библиотечной структуры зовётся у потребителя (RAII) — деструкция
перестала быть «внутри проекта». Ограничения v1/v2: `типфункции`, пространства
имён и обобщения через границу всё ещё непрозрачны; поля — примитивы/указатели
(владеющие поля в `срез` не экспортируются — как и внутри проекта).

**Тесты.** `либа2/потр2`: экспорт структуры с деструктором и sum-типа;
потребитель — объявление, литерал `{ фд = 42 }`, `выбор` с распаковкой payload,
`изменяемый`-передача (сверка типа по имени), RAII-вызов деструктора, grep .и;
негатив `потр2_чужой` — чужая структура в `изменяемый Файл` → «не совпадает».
Regression-корпус и ASan — зелёные.

## §35. Автоподключение стандартной библиотеки (stdlib)

**Задача.** После §32–§34 stdlib-модули (`stdlib/файл`) стали типизированными
(`Файл`, `Результат<целое64, целое32>`, проверка по `.и`, RAII-деструкторы), но
программа всё ещё требовала ручного `#содержит "файл.h"` + линковки `.so`.
Хотелось: для обычной программы stdlib подключается сама — функции, типы и
автолинк, без строк в коде пользователя.

**Решение.** Блок в `основа.c` (после `собрать_интерфейсы`, только когда есть
`интерфейсы && стандартная_библиотека && !библиотека && !статический`):
1. каталог stdlib ищется рядом с исполняемым файлом транспилятора
   (`/proc/self/exe` → `../stdlib/вывод`), переопределяется `KONDA_STDLIB`;
2. синтетический `#содержит "<абс.путь>/файл.h"` (typedef'ы C-типов приходят из
   `.h`, как и для обычных библиотек) + `собрать_интерфейсы_из_каталога` для
   `.и`; кодоген автодобавляет `-L <каталог> -l:файл.so` в линковку;
3. отключение: `--библиотека` (сборка самой stdlib), `--статический`
   (разделяемый `.so` статически не линкуется; пользователь увидит обычную
   ошибку «функция не объявлена»), наличие локальных `#содержит "…"` (кавычки —
   локальность; угловые `<stdio.h>` не мешают), коллизия имён;
4. коллизия имён сверяется по строкам `файл.и` («Ф имя», «Вар имя») против
   функций/вариантов в корне программы (варианты сум-шаблонов представлены
   конструкторами-функциями — ловятся первым циклом). При коллизии stdlib не
   подключается вовсе (иначе C-объявления и типы столкнулись бы с кодом
   программы), печатается предупреждение с решением.

**Урок по байтовым константам UTF-8.** Сравнение строк `.и` посимвольно через
«сырые» байты (`байт()[2] == 0xD0…`) и даже `strncmp(стр, "Вар ", 4)` давали
битые имена: «Вар » — это **7 байт** (3 буквы × 2 + пробел), а не 4; «Ф » — 3
байта. Правильно — `strncmp` на байтовую длину литерала (компилятор кодирует
UTF-8 сам), сдвиг на ту же длину. Вторая ловушка — **несвежие бинарники**: make
иногда не пересобирал CLI, и прогоны шли на старом коде, «опровергая» свежие
правки; с тех пор перед прогоном — `rm -f основа.o` или сверка маркера в
бинарнике.

**Тесты.** `стд_авто` (программа без `#содержит "файл.h"` читает
`/proc/self/cmdline` через stdlib; в `.c` — синтетический include), негатив
`--без-стандартной-библиотеки` (stdlib не видна → ошибка транспиляции),
`стд_коллизия` (своя `записать` — предупреждение, своя программа работает),
`стд_варианты` (свои `Успех`/`Провал` — коллизия, своё перечисление работает).
Санитайзер-прогон транспилятора форсирует `KONDA_STDLIB` (у `/tmp/квасан` нет
соседнего stdlib). Regression-корпус — зелёный.

## §36. Аргументы точки входа — единый `срез<символ*>` (старая форма снята)

**Контекст.** Прежняя сигнатура точки входа копировала C: `целое32
точка_входа(целое32 количество_аргументов, символ** аргументы)`. `аргументы`
был сырым `символ**` с зарегистрированной «связью» длины (argc): индексация
проверялась через отдельный рантайм-хелпер `аргументы_индекс(argc, …)`, а
литеральный индекс под охранником `количество_аргументов > N` доказывался
статически (спец-подсистема «связи массивов» + «ограничения длины», жившая
исключительно ради argv). Три беспоук-механизма (ремап имён `количество_аргументов`↔`argc`/`аргументы`↔`argv` в кодогене, хелпер
`аргументы_индекс`, связи/ограничения в семантике) — только для argv.

**Решение (пользователь): да, делать аргументы срезом; имя программы оставить в
срезе; старую форму убрать сразу.** Сигнатура теперь ровно одна:

```konda
целое32 точка_входа(срез<символ*> аргументы)
```

`аргументы` — обычный `срез<символ*>`, ВКЛЮЧАЮЩИЙ имя программы (`аргументы[0]`);
`длина(аргументы)` == argc. Это **заимствованный** (не владеющий) срез: argv
живёт всю программу, autofree к нему не применяется, а указатель из
`аргументы[i]` и сам срез безопасно возвращать (borrow-провенанс).

**Реализация (вертикальный срез).**
- *Парсер*: точка входа больше не игнорирует параметры — разбирает их штатно
  (`разобрать_параметр`). Заодно `разобрать_параметр` переведён на полную
  `съесть_тип_` (с `указ_эл`/`имя_эл`) — теперь `срез<T*>`/`срез<Структура>`
  поддержаны и как ТИП ПАРАМЕТРА (прежде терялись элемент-`*`/имя), а не только
  в объявлениях.
- *Семантика*: сверяет форму (ровно один параметр — срез символ-указателей, не
  ref/out, не `владеет`), объявляет `аргументы` срезом и метит его
  `безопасен_для_возврата`. Спец-объявления `количество_аргументов`/`аргументы`
  и `связь_добавить` для argv удалены (подсистема «связей» осталась в коде, но
  дормантна — единственный её потребитель был argv).
- *Кодоген*: C-сигнатура main без изменений — `int32_t main(int32_t argc, char
  **argv)`; пролог тела синтезирует `[[maybe_unused]] Срез аргументы = {
  (void*)argv, (size_t)argc };` с ИМЕНЕМ параметра. Дальше индексация,
  `длина(аргументы)` и `для … в аргументы` идут штатным путём среза (проверка
  границ `срез_доступ`, элизия доказанного/канонического доступа). Удалены: ремап
  имён, хелпер `аргументы_индекс` и его пролог, флаг `узел_использует_проверку_аргументов`. Любая программа с main теперь тянет
  `typedef Срез`+`срез_доступ` (нужны для синтетического среза).

**Осознанный компромисс.** Единственная утрата — статическое доказательство OOB
по охраннику `длина(аргументы) > N` для ЛИТЕРАЛЬНОГО индекса argv (было спецом
для указателя-с-длиной). Теперь `аргументы` — обычный срез: неизвестная на
компиляции длина → проверка в РАНТАЙМЕ (как у любого среза), memory-safety цела
(SIGABRT с сообщением вместо чтения за argv). Взамен — единая абстракция,
`длина`/итерация/borrow «бесплатно», минус три беспоук-механизма. Отключение
старой формы — полное: `(целое32 …, символ** …)` и пустая `()` теперь ошибка
семантики с подсказкой про правильную сигнатуру.

## §37. Строки — `срез<символ>`; реализация в транспиляторе, операции в stdlib

**Вопрос пользователя:** делать строки в stdlib или в транспиляторе? как
минимизировать проверки? **Решение:** `строка` = **`срез<символ>`** (UTF-8-байты).
Тип и литералы — в транспиляторе (только он видит литералы, статическую раскладку
`.rodata` и валидирует UTF-8 на компиляции); операции (`найти`/`разбить`/…) —
позже в stdlib как функции над `срез<символ>`, пересекающие `.и` (§34).

**Почему `срез<символ>`, а не новый checked-тип.** Прямой ответ на «минимизировать
проверки»: **не изобретать новую проверяемую сущность.** Строка-срез наследует всю
машинерию срезов даром — элизия границ в каноническом цикле (§20), доказуемый
конст-индекс, borrow/owned-различение, ref-проекции подстрок (§21). Ни одной новой
рантайм-проверки. Отдельный растущий `Строка{данные,длина,ёмкость}` (аналог Rust
`String`) — отдельный именованный тип в stdlib потом, когда понадобится
мутабельная сборка; ядро (неизменяемый вид + владеющий буфер) уже покрыто срезом.

**Минимизация проверок конкретно:** (1) байты, не символы — индексация байтовая,
O(1), проверка границ среза; юникод-итерация будет функцией stdlib, не платится,
пока не нужна; (2) UTF-8-валидность — инвариант КОНСТРУКЦИИ (литерал валиден на
компиляции; байты извне валидируются один раз на границе), не пер-доступная
проверка; (3) длина хранится в дескрипторе — ни одного `strlen`.

**Slice 1 (реализовано):** `срез<символ> с = "литерал"` — литерал становится
**заимствованным** срезом над `.rodata`:
`(Срез){ .данные = (void*)"лит", .длина = sizeof("лит") - 1 }`. `.длина` считает C
через `sizeof-1` (учитывает escape/UTF-8 без счётчика в Konda; компайл-тайм-длину в
семантике НЕ фиксируем → граница проверяется в рантайме для конст-индекса, а в
цикле `и < длина(с)` снимается структурно). Свойства среза: `владеет_срезом=0`
(borrow — `.rodata` не освобождается, autofree не трогает), `из_литерала=1`
(запись `с[i]=…` запрещена — уже существующей проверкой rodata),
`безопасен_для_возврата=1` (статика переживёт возврат). NUL сохранён → `.данные`
годна как C-строка (совместимость с `printf`, инвариант №3 цел). **Обратная
совместимость полная:** `символ*`-литералы не тронуты (литерал → `срез<символ>`
ТОЛЬКО в контексте объявления `срез<символ>`; в `printf`/`символ*` — как был).

**Границы v1 / дальше (отдельными срезами):** алиас-имя `строка` (контекстное,
чтобы не отнимать имя-переменную); коэрция литерала на call-site и в присваивании
(`с = "…"`), не только в объявлении; ВЛАДЕЮЩИЕ строки (`выделить`, f-строки →
`срез<символ>`, конкатенация); NUL-хелпер `.вкси()` для вычисленных строк в
C-функции; юникод-итерация и базовые операции в stdlib; снятие ограничения §22 не
требуется (символ — примитив).

## §37 (продолжение). Строки — slices 2—5: коэрция, владеющие, алиас, вкси

Слайс 1 (объявление литерала `срез<символ> с = "…"` → borrow над .rodata) уже
описан выше. Здесь — четыре следующих слайса, всё в тот же §37:

**Slice 2 — коэрция литерала на call-site и в присваивании.** `ф("литерал")`
при параметре `срез<символ>` и `с = "литерал"` при `с: срез<символ>` теперь
работают: семантика метит узел-литерал `->срез=1`, кодоген эмитит его как
`(Срез){(void*)"…", sizeof("…")-1}`. **Guards** (иначе нарушение памяти):
- **Владеющая цель** (`с` из `выделить`) + литерал → ошибка компиляции с
  подсказкой: буфер бы утёк, и autofree в конце области попытался бы
  `free(.rodata)` → крах.
- **`владеет`-параметр** + литерал → ошибка: функция освободила бы .rodata.
- **Возврат** «`вернуть "…"`» как `срез<символ>` → ошибка: возврат среза =
  передача владения, вызывающий autofree'ил бы .rodata. Правильный путь —
  вернуть владеющую строку (см. slice 3).
Присвоение литерала *заимствованной* строковой переменной — безопасно (`borrow ←
borrow` над .rodata: ни утечки, ни `free .rodata`); провенанс цели обновляется
(`из_литерала=1`, `безопасен_для_возврата=1`, `с_нулем=1`).

**Slice 3 — владеющие строки: `выделить(N)` и f-строки в контексте среза.**
- `срез<символ> с = выделить(N)` уже работает как обычный владеющий срез
  (`символ` — примитив; ограничение §22 не касается). Запись `с[i]=…`,
  `длина(с)==N`, autofree в конце области, move-возврат из функции.
- **F-строка в `срез<символ>`-контексте**: та же машинерия коэрции на всех трёх
  сайтах (`= f"…"`, `ф(f"…")`, `вкси(f"…")`). Кодоген эмитит
  `({ int _n = snprintf(_kfN, sizeof(_kfN), "fmt", …); (Срез){(void*)_kfN,
  (size_t)clamp(_n, 0, sizeof-1)}; })`. Тот же `_kfN`-буфер, что у обычной
  f-строки (§символьные литералы), — потокобезопасно и реентерабельно (каждой
  вставке свой буфер, поднят в начало функции). Срез **заимствован** над
  стек-буфером текущей функции. **Возврат f-строки как `срез<символ>`** —
  ошибка (стек умрёт вместе с функцией → dangling).

**Slice 4 — контекстный алиас `строка` = `срез<символ>`.** Читаемость без нового
ключевого слова: `строка` НЕ отнимает имя-переменную (инвариант «не отбирать
имена без нужды»). Распознаётся только на позиции ТИПА: параметр функции,
локальное объявление (`строка х = …` — если за словом идёт идентификатор), тип
возврата (`строка ф() { … }` — если за словом идёт имя функции). Иначе `строка`
— обычный идентификатор: `целое32 строка = 42` работает как раньше. Реализация —
одна ветка в `съесть_тип_` + предикат `это_алиас_строка` в трёх точках
диспетчеризации (параметр × 2, локальная декларация, top-level функция).

**Slice 5 — `вкси(с)` — NUL-хелпер для передачи строки в C-функции.** Возвращает
`символ*`, годный для `printf("%s", вкси(с))`, `fopen(вкси(имя))` и т.п.
Двух-путная реализация — **zero-cost для литералов и f-строк**:
- Флаг `с_нулем` на Символе и на узле-вызове «вкси»: семантика доказывает, что
  байт `.данные[длина]` равен 0 (для литерала — NUL в .rodata за длиной; для
  f-строки — snprintf всегда пишет NUL; для переменной, инициализированной
  литералом/f-строкой — свойство пропагируется).
- **Zero-cost путь**: кодоген эмитит `((char*)(с).данные)` — прямой каст, ноль
  инструкций.
- **Копия+NUL путь** (для `выделить`-строк, параметров, любых источников без
  доказанного NUL): стек-буфер `_kvN[1024]` (по одному на call-site, поднят в
  начало функции), `memcpy` длиной, добавление `\0`. Усечение при переполнении
  буфера — безопасно.
Приём аргумента: и `срез<символ>`-переменная, и литерал/f-строка прямо на месте
(`вкси("abc")`, `вкси("n=\(x)")`) — литерал коэрцируется через уже описанный
путь.

**Что дальше НЕ покрыто (следующие слайсы отдельно):** конкатенация строк (`+`),
подстроки как ref-проекции (§21 применить к char-slice), сравнение (перегрузка
`==`), юникод-итерация по кодоточкам, операции в stdlib (`найти`, `разбить`,
`верхний_регистр`, …).

## §38. Условия/циклы без обрамляющих `(…)` (Rust-стиль); старая форма `для (…)` снята

**Решение пользователя.** `если`/`иначе если`/`пока`/`для`/`для_каждого`
пишутся БЕЗ круглых скобок вокруг условия/заголовка — как в Rust:

```konda
если н > 2 { … } иначе если н == 2 { … } иначе { … }
пока к < 3 { … }
для целое32 и = 0; и < н; и = и + 1 { … }
для_каждого э из с { … }
```

**Почему нет неоднозначности.** Тело всегда начинается с `{`, а `{` не может быть
частью выражения: структурные и массив-литералы (`{ поле = … }` / `{ 1, 2 }`)
разбираются ТОЛЬКО в позиции инициализатора (`разобрать_значение_инициализатора`),
а не в `разобрать_выражение`. Поэтому «выражение до `{`» разбирается однозначно
(нет проблемы Rust с `if x == Foo { … }` — у Konda нет `Имя{…}`-литералов-выражений).

**Реализация (парсер, `разбор.c`).** Из `разобрать_если`/`разобрать_пока`/
`разобрать_для_`/`разобрать_для_каждого` убраны обязательные
`съесть(КРУГЛАЯ_ОТКР/ЗАКР)` — условие/заголовок разбираются напрямую до `{`.
Транспилятор при этом стал ПРОЩЕ (меньше `съесть`-вызовов), что и требовалось
(«убрать старое, если поддержка усложняет»).

**Совместимость и «снятие старого».**
- `если`/`пока`: скобки вокруг условия — это обычное скобочное выражение, поэтому
  `если (x) { }` по-прежнему валидно (== `если x { }`). Запретить его нельзя, не
  сломав легитимную группировку `если (a + b) > 0` — поэтому и не запрещаем.
- `для`/`для_каждого`: заголовок содержит `;`/`из`, а не выражение, поэтому
  обрамляющая `(` больше не разбирается — **старая форма `для (…)` /
  `для_каждого (…)` снята** (ошибка разбора «неожиданное выражение»). Тесты,
  фикстуры и доки мигрированы на бесскобочную форму. `параллельно для … редукция(имя) { }`
  — та же бесскобочная форма (у `редукция(имя)` свои скобки остаются).

Тест `без_скобок` покрывает все пять конструкций; `скобки_условия_ок` — что
`если (…)` ещё валидно; `для_скобки_снято` — что `для (…)` теперь ошибка.

## §37 п.6. Возврат заимствованных строк — ВЫВОД владения возврата (без keyword, без рантайма)

**Проблема:** `вернуть "литерал"` как `срез<символ>` отклонялся (возврат среза =
передача владения → вызывающий autofree'ил бы `.rodata` → крах). Фабрики
констант-строк (`код_ошибки`, `приветствие`) были невыразимы без сдачи
абстракции (тип `символ*`) или лишней heap-аллокации (`выделить`+копия).

**Решение пользователя:** делать вариант «вывод свойства функции» (как чистота),
с **максимальным упором на нулевую рантайм-цену**. Отвергнуты: рантайм-бит
«borrowed» в дескрипторе (рантайм + ломает 16 байт), разделение типов
(Rust `String`/`&str`).

**Ключевой рефрейминг:** «владеющий vs заимствованный» возврат — это ОДНА строчка
на call-site (регистрировать результат в autofree или нет). Оба на уровне C —
`Срез` (16 байт), рантайм-тега нет. Значит задача = статически вывести на функцию
бит «возврат заимствован», как уже выводится `чистая`.

**Реализация (аналог `вывести_чистоту`):**
- Пред-проход `вывести_владение_возврата` (до анализа тел). Классификация
  возврата среза: литерал `"…"` → ЗАИМСТВ.; `выделить`/`клон`/владеющий
  идентификатор → ВЛАДЕЮЩИЙ; `вернуть G()` → наследует бит G (**fixpoint** для
  рекурсии/цепочек, как чистота). Функция *заимствует-возврат*, если ВСЕ возвраты
  заимствованные и ни одного владеющего.
- Бит хранится в `СигнатураФункции.возврат_заимствован` (+ `возврат_смешанный`).
  Проверка возврата в теле: у *заимствующей* функции `вернуть "литерал"` — ОК
  (метится `выр->срез=1`, кодоген даёт `(Срез){лит,sizeof-1}`); у *смешанной*
  (есть и владеющий возврат) — ОШИБКА (единообразие: вызывающий делает ОДНО
  статическое решение; копию НЕ навязываем — ноль рантайма, максимум статики).
- **Call-site без связи с кодогеном:** семантика при типизации `УЗЕЛ_ВЫЗОВ`
  переносит бит с сигнатуры на call-узел (`узел->возврат_заимствован`). Кодоген
  на `срез с = ф()` регистрирует autofree ТОЛЬКО если бит=0. Работает и для
  библиотечных функций (у них нет AST-узла — но call-узел есть). **Компайл-тайм,
  нулевая рантайм-цена.**
- **Cross-library:** бит сериализуется в `.и` вторым полем строки `Ф имя <бит>`
  (старые `.и` без него → 0, владеющий; совместимо — прежние библиотеки
  владеющие). Потребитель читает бит в сигнатуру и решает autofree корректно.
  Урок: детектор коллизий stdlib (`основа.c`) брал имя функции из `.и` как
  `строки+3` + `strlen` — с новым вторым полем ловил «имя 0»; чиним обрезкой по
  первому пробелу (как «Вар имя» без второго поля).

**Стоимость по паттернам:** фабрика литералов — **0** (нет ни alloc, ни free);
`выделить`-билдер — как раньше (owned move); смешанный — ошибка компиляции (не
рантайм). f-строка-возврат — всегда ошибка (стек-буфер умирает при возврате).

**Границы v1:** заимствованными считаются возвраты ЛИТЕРАЛОВ и `вернуть G()`
(borrow). Возврат borrow-ПАРАМЕТРА (`вернуть srez_параметр`) пока остаётся
ошибкой (как и было) — отдельный слайс (second-class borrow, как у указателей).

## §39. Портируемость сборки: Linux/BSD/macOS — единый транспилятор, OS-гейтинг флагов

**Что.** Транспилятор (`Makefile`) и вызовы `cc` из `скомпилировать_си`
([ввод_вывод.c]) переведены на переносимую POSIX-модель: работает на Linux, на
всех BSD и на macOS. Раньше многие флаги были GNU-ld/Linux-only и падали бы на
Darwin (ld64) на компиляции сгенерированной программы или .konda-библиотеки.

**Что перенесено (по OS):**

- **Суффикс разделяемой библиотеки** — единая константа `КОНДА_СУФФИКС_БИБЛ` в
  `транспилятор.h` (`"dylib"` на `__APPLE__`, `"so"` на прочих POSIX). Используется
  и эмитом артефакта (`скомпилировать_си`), и автоподключением stdlib
  (`собрать_интерфейсы_из_каталога` / `собрать_интерфейс_из_h` в `интерфейс.c`).
  Два источника → неизбежный дрейф; одна точка правды закрывает.
- **`-Wl,-z,relro/-z,now/-z,noexecstack`** — GNU-ld/LLD-опции, есть на Linux и
  BSD. На `__APPLE__` их НЕ эмитим (`ld64` не знает `-z*` → падение с «unknown
  option»). Mach-O даёт NX-стек и защиту GOT платформой.
- **`-fstack-clash-protection`** — надёжен в gcc≥8 и clang≥13 на Linux/BSD. На
  Darwin у AppleClang свои номера версий и историческая нестабильность → не ставим.
- **`-fstack-protector-strong`** — переносимо, ставим везде.
- **`-rdynamic`** — GNU-ld: экспорт символов в `.dynsym` для `backtrace_symbols_fd`.
  На Darwin не нужна (dyld/CoreSymbolication всегда даёт символы) — не эмитим.
- **`-funwind-tables`** — переносимо (gcc/clang на всех POSIX). Оставляем.
- **Разделяемая библиотека**: ELF (`-shared`) vs Mach-O (`-dynamiclib` +
  `-Wl,-install_name,@rpath/<имя>.dylib`, чтобы потребитель находил её по своему
  `-rpath`). `-fPIC` — переносим, ставим в обеих ветках.
- **jemalloc**: на Linux — `-l:libjemalloc.so.2` (версионный soname без
  dev-symlink, GNU-ld/LLD-расширение); на BSD/macOS — обычное `-ljemalloc`
  (Homebrew/pkg дают dev-symlink), т.к. `-l:name` их линковщики не знают.
- **`-static`**: на macOS отказываем понятно (нет статической libSystem, Apple
  документирует запрет) — а не роняем поздно на линковке.
- **Панический пролог**: уже был `#if defined(__GLIBC__)` для `execinfo.h` —
  на musl/macOS/BSD деградирует до простого `abort()` (переносимость сохранена).
  Не тронуто, но уместно упомянуть — часть общей картины.
- **Makefile**: ELF-ветвь принимает `Linux/FreeBSD/OpenBSD/NetBSD/DragonFly` (одна
  ветка); Darwin — своя (`-dynamiclib`, `.dylib`, `@loader_path`).

**Тест-регрессия** (Linux): `флаги_сборки` — гарантирует, что Darwin-специфичные
флаги (`-dynamiclib`, `-install_name`, `@rpath`, `@loader_path`) НЕ протекают в
argv на Linux. Прежние проверки Linux-флагов (`-Wl,-z,*`, `-fstack-clash-*`,
`-l:libjemalloc.so.2`) не меняются — на Linux эмит прежний.

**Что осталось Linux-специфичным (осознанно).** `tests/run.sh` строит проверки
против конкретных Linux-строк argv (`-l:libjemalloc.so.2`, `-Wl,-z,relro`, …),
использует `ldd` и `-l:name`. Портирование самих ТЕСТОВ на macOS/BSD — отдельная
задача (когда появится CI на нужном хосте). Транспилятор — уже переносим.

## §40. Предопределённые макросы: режим сборки и платформа (для «#если …»)

**Запрос пользователя.** Дать разработчику писать разный код для разных сборок:
`#если дебаг`/`#если релиз`, и для платформ — `#если линукс` и т.д. (условная
компиляция уже была реализована — §6/§«Безопасные макросы»; не хватало ровно
ПРЕДОПРЕДЕЛЁННЫХ имён, чтобы не задавать их руками через `-D`).

**Выбор пользователя (AskUserQuestion):**
1. Объём — **режим + ОС + архитектура + разрядность** (полный набор).
2. Имена — **только русские** (без английских синонимов).
3. Платформы — **`макось`** для macOS; **`бсд`** (общий) **И** конкретные
   `фрибсд`/`опенбсд`/`нетбсд` (плюс `драгонфлай` для полноты §39).

**Набор макросов** (определён ТОЛЬКО активный; неактивное имя в `#если` = 0):
- режим: `дебаг` | `релиз` (по флагу `--релиз`);
- ОС: `линукс` | `макось` | `бсд` (+ конкретный `фрибсд`/`опенбсд`/`нетбсд`/`драгонфлай`);
- архитектура: `x86_64` | `арм64` | `рискви64` | `x86` | `арм` | `рискви`;
- разрядность: `бит64` | `бит32`.

**Реализация.** `макросы_предопределить(таблица, релиз, триплет)` в [макросы.c]
(вызов в [основа.c] ПОСЛЕ разбора аргументов, ДО `условная_компиляция`):
- режим — `задать_если_нет(релиз ? "релиз" : "дебаг")`;
- платформа — из **ТРИПЛЕТА** цели, если задан `--целевая-архитектура`
  (`платформа_из_триплета`: substring-поиск `linux`/`darwin`/`freebsd`/…, арх по
  `x86_64`/`aarch64`/…), иначе из **ХОСТА** (`платформа_хоста`: compile-time
  макросы компилятора `__linux__`/`__APPLE__`/`__x86_64__`/…, разрядность —
  `sizeof(void*)`). Цель важнее хоста: код компилируется ПОД цель.

**Инварианты/тонкости:**
- **`-D` побеждает предопределённый** — `задать_если_нет` не перезаписывает уже
  заданное (`-D` обрабатывается в цикле аргументов раньше). Так `-D линукс=0`
  локально гасит ветку `линукс`.
- **Имена-макросы не отнимают имён у кода** — таблица макросов отдельна от
  пространства идентификаторов Konda (используется лишь в условиях `#если`).
- **Ноль рантайма** — неактивные ветки вырезаются из токенов до разбора, в C не
  попадают (как и вся условная компиляция).

**Заодно: слова-операторы `не`/`и`/`или` в `#если`** (= `!`/`&&`/`||`). Язык
русскоязычный (в теле кода уже есть `и`/`или`), поэтому `#если линукс и арм64`,
`#если дебаг или релиз`, `#если не релиз` читаются естественно. Реализованы в
вычислителе (`слово_оп` с проверкой границы слова, чтобы `или` не путался с `и`, а
макрос `линукс` — с оператором). C-запись `&&`/`||`/`!` сохранена.

## §41. C23 «выровнять(N)» (alignas) и «встроить("файл")» (#embed) — русские имена

**Запрос пользователя.** Дать возможности C23: `alignas` (выравнивание) и `#embed`
(встраивание файла), «только назвать по-русски».

**Имена (выбор транспилятора):** `выровнять(N)` = `alignas(N)`, `встроить("файл")`
= `#embed "файл"`.

**`выровнять(N)` — alignas.** Ключевое слово (`ТОКЕН_ВЫРОВНЯТЬ`), ведущий
спецификатор объявления (в любом порядке со `статический`/`конст`) и полей
структуры. `N` — положительная СТЕПЕНЬ ДВОЙКИ (требование C для alignas), проверка
в семантике (понятная ошибка Konda вместо позднего диагноза cc). Кодоген эмитит
`alignas(N) ` среди спецификаторов — и для локальных/глобальных объявлений
(`эмит_выравнивание`), и для полей (`typedef struct { alignas(64) … }`). Нулевая
рантайм-цена. Область v1: скаляры, массивы, поля структур, глобальные конст.

**`встроить("файл")` — #embed.** Инициализатор БАЙТОВОГО массива с ВЫВОДИМЫМ
размером: `конст неподписанный целое8 имя[] = встроить("путь")`. `встроить` —
КОНТЕКСТНОЕ слово (идентификатор + `(`), имя-переменную не отнимает. Пустые `[]`
(флаг `выводимый_размер`) допустимы ТОЛЬКО с `встроить` (иначе размер неоткуда
взять — понятная ошибка). Элемент обязан быть `неподписанный целое8` (uint8_t;
байты 0–255 без сужения). Кодоген: `static const uint8_t имя[] = {\n#embed
"путь"\n};` (static+const → .rodata; C подставляет байты и ВЫВОДИТ размер).

*Безопасность.* Длина неизвестна транспилятору (её знает C через `sizeof`),
поэтому индексация ВСЕГДА идёт через рантайм-проверку `массив_доступ` по
`sizeof(имя)/sizeof(имя[0])` — memory-safety цела (выход за границы → abort с
сообщением), просто без статических доказательств (даже литеральный индекс
проверяется в рантайме). Для этого обобщён индексный путь массива: `база->массив`
без требования `длина_известна` (при известной длине — прежние статические
проверки/элизия; при выводимой — только динамика). Детектор рантайм-пролога
массивов больше не исключает числовой индекс (иначе `имя[0]` embed-массива
эмитил бы `массив_доступ` без пролога).

*Разрешение пути.* `#embed "путь"` в C ищет файл рядом с `.c` (в `вывод/`) и по
`--embed-dir`, но НЕ по `-I`. Поэтому при наличии `встроить` транспилятор
добавляет `--embed-dir=<каталог источника>` в вызов cc
(`программа_использует_встроить` → флаг в `скомпилировать_си`); ставится ТОЛЬКО
когда embed используется (не навязываем флаг старому cc на не-embed сборках).
Тесты кладут файл и рядом с исходником, и в `вывод/` (санитайзер-прогон пересобирает
`вывод/*.c` напрямую, без `--embed-dir`).

**Оба — ноль рантайма, C23.** Требуют cc с поддержкой C23 (gcc≥15/clang≥19 —
проект и так их требует). Тесты: `выровнять_база`/`выровнять_негатив`,
`встроить_база`/`встроить_границы`/`встроить_негатив`/`встроить_пусто`.

### §41 (дополнение). Динамический/освобождаемый embed — рассмотрено, НЕ делаем

Вопрос: сделать «динамический embed», который освобождается при неиспользовании и
«не занимает ОЗУ». **Решение пользователя: ничего не строить, оставить статический.**

Обоснование (развеян миф про ОЗУ): статический `#embed` кладёт байты в `.rodata`,
а это НЕ постоянно занятая оперативка — секция лежит в файле-бинарнике,
отображается mmap'ом, страницы подгружаются лениво (demand paging) и, будучи
чистыми и подкреплёнными файлом, ВЫТЕСНЯЮТСЯ ядром под нагрузкой. Реальная цена —
размер бинарника, а не резидентная RAM. Для read-only данных heap-копия была бы
хуже (вторая, dirty-копия). Физика: данные должны лежать либо в бинарнике
(вытесняемая rodata), либо во внешнем файле (бинарник не самодостаточен) —
«нигде» невозможно.

Если когда-нибудь понадобится ТРАНЗИЕНТНАЯ рабочая память/меньший бинарник —
зафиксированы варианты «выше C»: (A) `встроить` во ВЛАДЕЮЩИЙ `срез<…>` (heap-копия,
RAII-free); (B) СЖАТЫЙ embed + распаковка по требованию в RAII-срез (нужен
распаковщик в stdlib) — «сладкая точка»; (C) внешний ленивый файл через stdlib
`файл` + владеющий срез (уже почти возможно). Пока — не требуется.

## §42. Срезы строк как в Python (`s[a:b]`) — заимствованный ВИД по умолчанию

**Запрос пользователя:** «сделай срезы строк как в питоне». **Три развилки
проработаны и вынесены на AskUserQuestion; ответы пользователя:**

1. **Модель памяти — «оба»**: `s[a:b]` по умолчанию → *заимствованный вид* в тот
   же буфер (Rust-модель `&s[a..b]`), а *владеющая копия* (Python-модель) — по
   явному запросу `копия(s[a:b])`. Обоснование: `Срез = {данные, длина}`, под-вид
   = `{данные+начало, конец−начало}` — **0 аллокаций, 0 рантайма** (кроме проверки
   границ) → строго по инварианту №1. Результат-вид — заимствованный срез, живёт
   не дольше родителя; borrow-машинерия срезов (§21 second-class ref, §37 п.6
   вывод владения возврата) уже это обеспечивает: возврат вида за пределы жизни
   родителя ловится теми же проверками, что и возврат `выделить`-среза. `копия(…)`
   даёт независимый владеющий срез со стандартным autofree (как `выделить`).
2. **Индексы — байтовые с проверкой UTF-8-границы** (Rust-семантика, не Python по
   кодоточкам): O(1); индексы в БАЙТАХ (консистентно с `длина()` и всей моделью
   §37, длина строки в байтах). Хелпер проверяет, что `начало` и `конец` попадают
   на границу UTF-8-символа (ведущий байт `!= 10xxxxxx`) — иначе `abort` с
   сообщением (как выход за границы). Так под-срез строки всегда валидный UTF-8;
   молчаливого рассечения символа нет. Отказ от кодоточек — они дали бы O(n)
   проход и рассогласование с байтовой длиной везде в языке.
3. **Объём v1 — база + отрицательные индексы, БЕЗ шага**: `s[a:b] s[a:] s[:b]
   s[:]` плюс `s[-1:] s[:-2]` (отсчёт с конца: `i<0 → длина+i`). Шаг `s[a:b:c]`
   отклонён для v1: шаг≠1 не непрерывен → сломал бы единый zero-cost путь вида,
   потребовав владеющую копию и отдельную машинерию. `s[::-1]`/`s[::2]` — позже,
   если понадобится.

**Реализация (вертикальный срез).** Лексер: одиночный `:` → новый
`ТОКЕН_ДВОЕТОЧИЕ` (значим только внутри `[…]`; `::` для пространств и `?:` не
затронуты — двухсимвольные распознаются жадно первыми; имя-переменную `:` не
отнимает). AST: `УЗЕЛ_СРЕЗ_ДИАПАЗОН`, дети `[база, начало?, конец?]`, флаги
`есть_начало`/`есть_конец` (какие концы присутствуют). Парсер: в обоих index-
сайтах (идент-форма и постфикс-форма lvalue) после `[` определяем срез по наличию
`:`; плоский индекс идёт прежним путём без изменений. Семантика: база обязана быть
`срез<T>` (иначе ошибка); тип результата = тот же `срез<T>`; `начало`/`конец` —
целочисленные; результат-вид помечается заимствованным (не регистрируется в
autofree). UTF-8-проверка активна только для `срез<символ>`. Кодоген: хелпер
`срез_подсрез(Срез, long начало, long конец, size_t эл_размер, int utf8, int
строка)` — нормализует отрицательные, проверяет `0 ≤ начало ≤ конец ≤ длина` и
(при `utf8`) границы символов, возвращает `{данные+начало*эл, конец−начало}`.
`копия(срез)` — владеющий клон через `срез_клон`/`выделить` + autofree.

**Что НЕ покрыто (следующие слайсы):** шаг, конкатенация (`+`), сравнение (`==`),
`найти`/`разбить`/регистр (в stdlib), юникод-итерация по кодоточкам.

## §43. Аудит-фиксы: дыра элизии границ, беззнаковая арифметика, OOM клона, батч парсера

Итог глубокого анализа проекта (по запросу пользователя). Четыре подтверждённых
дефекта с воспроизведением (ASan/запуск) + завершение батч-режима парсера. Архитектурные
развилки пользователь подтвердил через AskUserQuestion (см. ниже).

**Ф1 — дыра безопасности памяти (критично, инвариант №1).** Элизия проверки границ
(BCE) в каноническом цикле (`распознать_безопасный_цикл`) и guard-условии
(`распознать_безопасное_условие`) доверяла `имя_изменяется_в`, а та видела мутацию
индекса/границы ТОЛЬКО как присваивание `и = …` — но НЕ как передачу в
`изменяемый`/`вывод`-параметр (кодоген подставляет `&и`, функция меняет переменную
вызывающего). Тот же класс, что «Урок 17.07», но в ДРУГОЙ функции: 17.07 чинил
`собрать_изменяемые`, а BCE опирается на независимую `имя_изменяется_в`. Итог —
`для и { взорвать(и); с[и]=7 }` (взорвать(изменяемый и)) генерировал ПРЯМОЙ доступ без
`срез_доступ` → heap-buffer-overflow (подтверждён ASan; так же и guard-режим
`если (и < длина(с)) { … }`). **Решение пользователя (AskUserQuestion): «Точно, по
режиму параметра».** `имя_изменяется_в` получила аргумент `Анализатор *а` и в узле
`УЗЕЛ_ВЫЗОВ` резолвит сигнатуру через `найти_сигнатуру_по_имени` (ровно как
`собрать_изменяемые`): имя считается изменённым, только если передано в параметр
`по_ссылке > 0`. Ноль регресса скорости — `печатать("%d", и)` (по значению) быстрый
путь сохраняет (проверено). Срез `с` мутацией через ref не грозит (срезы не
передаются по ссылке — уже запрещено), поэтому его прямое переприсваивание ловилось и
раньше. Тесты: `сохранить_при_ref_индексе`, `сохранить_при_ref_guard` (обе → код 134
рантайм-проверки), `элиминация_при_вызове_по_значению` (быстрый путь цел).

**Ф2/Ф3/Ф-float — беззнаковая/вещественная арифметика в отладке (корректность,
режим по умолчанию).** Guard'ы `делить_безопасно`/`сдвиг_безопасно` считали операцию,
приведя операнды к ЗНАКОВОМУ `long`. Следствия (только отладка; релиз без guard был
прав): (Ф2) `неподписанный целое64` деление/остаток со старшим битом — неверный
результат (`(2⁶⁴−1)/2` давало `0`) и ложный abort при делителе `2⁶⁴−1`; (Ф3)
беззнаковый `>>` — арифметический вместо логического; (Ф-float, попутно найден)
ВЕЩЕСТВЕННОЕ деление тоже гейтилось (`делить_безопасно((long)double…)`) → `7.0/2.0`
давало усечённое целое. **Решение пользователя: «Проверка + нативное выражение».**
Прологи заменены на ПРОВЕРЯЮЩИЕ-ТОЛЬКО хелперы `конда_чек_делителя(делитель, делимое,
знаковый, разрядность, строка)` и `конда_чек_сдвига(бит, разрядность, строка)`; сама
операция кодогеном эмитится в РОДНОМ типе через GNU statement-expression + C23
`typeof` (single-eval операндов через временные — побочные эффекты один раз):
`({ typeof(Л) _чдл=(Л); typeof(П) _чзн=(П); конда_чек_делителя(…); _чдл / _чзн; })`.
Беззнаковое считается беззнаково, `>>` логичен/арифметичен по типу автоматически.
Вещественное деление в семантике исключено из guard (`&& тип_целочисленный(рез)`) —
÷0 у float определено (inf/nan), не UB. Попутно знаковый MIN/-1 теперь прерывается на
ПРАВИЛЬНОЙ разрядности результата (раньше только 64-бит). Тесты: `деление_беззнак64`,
`сдвиг_беззнак64`, `деление_вещ`, обновлены greps (`конда_чек_делителя`).

**Ф4 — `срез_клон` при OOM (надёжность).** В отличие от `срез_выделить`, при
`calloc==NULL` возвращал `{длина=N, данные=NULL}`; первый `срез_доступ` (индекс<длина
проходит) разыменовал бы NULL → грязный SIGSEGV вместо чистого сообщения. Добавлен
`if (длина!=0 && данные==NULL) конда_прервать()` — как у `срез_выделить` (инвариант
«отказ = сообщение + abort»).

**Батч парсера — на уровне операторов.** Инфраструктура батча (`батч_ошибки`,
`восстановиться_на_верхнем`, плюмбинг CLI `синт_ошибки`) уже была, но восстановление
шло ТОЛЬКО на границе верхнего уровня → внутри одного тела функции видна была лишь
первая ошибка. **Решение пользователя: «На уровне операторов».** Добавлена
`восстановиться_на_операторе` (пропуск до значимого перевода строки / `}` / EOF, с
гарантией прогресса) и ветка в `разобрать_блок`: при ошибке в батч-режиме — записать,
сбросить `диаг`, освободить битый узел, восстановиться, продолжить (предел 32). Теперь
все синтаксические ошибки тела видны за прогон. Тесты: `синтаксис_батч_тело` (3 из 3),
`синтаксис_батч_смешанный` (по ошибке в двух телах). Тонкость модели A (Go-подобная
автоподстановка `;`): оператор, оканчивающийся бинарным оператором (`… +`), продолжается
на следующую строку — тогда две «строки» суть один незавершённый оператор (одна ошибка).

Валидация: полный `run.sh` зелёный, включая санитайзер-свипы (транспилятор под
ASan+UBSan по всему корпусу И пересобранный сгенерированный C под ASan+UBSan) — новый
statement-expression-кодоген деления/сдвига прогнан по всему корпусу чисто.

**Отложено пользователем (это потом):** сканер C-заголовков и всё, что связано со
stdlib. **Снято из планов:** транслитерация имён в ASCII (держим кириллицу как есть,
C23 UTF-8-идентификаторы, см. §7).

## §44. Null-safety: возврат «возможно<T*>» и TOCTOU сужения охранника

Аудит на TOCTOU/double-fetch «в пределах языка» (сгенерированного кода, а не
транспилятора). Проверены места «проверка → использование»:
- индексация срезов/массивов — один атомарный снимок (`срез_доступ`/`массив_доступ`
  берут значение по значению; индекс вычисляется один раз) → double-fetch нет;
- элиминация границ — компайл-тайм-доказательство, рантайм-чтений нет;
- `выбор` (match) — выбираемое кладётся во временную `_выбор_N` (снимок) → нет;
- `для_каждого` — срез копируется в дескриптор `__коллекция` (одна оценка), массив
  гарантированно идентификатор → нет;
- составное присваивание (`+=`) отсутствует в языке → desugar-double-fetch нет;
- арифметические guard'ы — single-eval через statement-expression (§43 Ф2/Ф3);
- `атом<T>` — единственное разделяемое состояние; каждый реальный доступ к памяти
  несёт СОБСТВЕННУЮ проверку границ против длины контейнера, поэтому логическая
  гонка атомика не даёт memory-safety-TOCTOU (как `AtomicI32` в Rust).

**Найдена настоящая дыра (Ф5, null-safety/TOCTOU).** Nullability ВОЗВРАТА функции
(`возможно<Узел*> найти(…)`) нигде не отслеживалась: `СигнатураФункции` не несла
такого бита, а `выражение_может_быть_нуль` учитывало лишь литерал `нуль` и
переменную-`возможно`. Следствие — результат nullable-вызова считался НЕнулевым:
- `возможно<Узел*> п = найти(5); п.знач` — дереф без охранника компилировался;
- `найти(5).знач` — прямой дереф временного компилировался;
- `Узел* п = найти(5)` — nullable в ненулевой указатель проходил молча;
- **TOCTOU**: `если (п != нуль){ п = найти(9); п.знач }` — проверили не-нуль,
  переприсвоили nullable, разыменовали возможный нуль (`найти`→`нуль` → null-дереф).

**Фикс.** (1) `СигнатураФункции.возврат_возможно` = `функция->возможно`, ставится
при построении сигнатуры. (2) Общий предикат `выражение_может_быть_нуль(а, выр)`:
`нуль`-литерал | несужённая `возможно`-переменная (`Символ.может_быть_нуль`) | вызов
функции с `возврат_возможно`. (3) Применён на ВСЕХ путях: реассайн указателя,
объявление `Структура*`/примитив-`*`, прямой дереф поля через `.`. Non-null-цель
теперь отвергает любое nullable-значение (не только литерал `нуль`); `возможно`-цель
получает `может_быть_нуль` из предиката (реассайн под охранником в nullable-вызов
СБРАСЫВАЕТ сужение — TOCTOU закрыт). Ноль рантайма — проверка статическая (инв. №1).

Тесты: `нуллабл_вызов_объявление`/`_прямой`/`_toctou` (→ ошибка),
`нуллабл_вызов_охранник` (позитив: сужение работает, null-путь в «иначе»),
`ненуллабл_вызов` (позитив: НЕнулевой возврат дереференсится без охранника — не
переусердствовали). Полный `run.sh` + оба санитайзер-свипа — чисто.

**v1-ограничение:** для БИБЛИОТЕЧНЫХ функций (сигнатура из `.и`) и указателей на
функции `возврат_возможно` пока не переносится (формат `.и` бита не несёт) — их
nullable-возврат считается ненулевым. Пользовательские функции (основной случай)
покрыты. Также не отслеживается nullability ПОЛЯ-структуры (`объект.поле` с
`возможно<T*>`-полем) — отдельный слайс, как и раньше.

## §45. Составное присваивание «+= -= *= /= %= &= |= ^= <<= >>=» (десугар)

Запрос пользователя. Реализовано как **чистый десугар в парсере**:
`цель ОП= значение` → `цель = цель ОП значение`. Так переиспользуется ВСЯ машинерия
бинарных операторов без правок семантики/кодогена:
- рантайм-guard'ы деления/сдвига/переполнения (§43) — работают через `/=`,`<<=`,`+=`;
- нативный тип операции (§43): беззнаковое `<<=`/`/=` считается верно;
- перегрузка операторов: `v += w` → `v = оператор+(v, w)` для структур;
- проверки типов, `конст`-иммутабельность, гейт арифметики указателей за
  `небезопасно` — всё наследуется от обычного присваивания.

**Лексер.** Новый `ТОКЕН_СОСТАВНОЕ_ПРИСВАИВАНИЕ`. `тип_оператора_по_срезу`
классифицирует `X=` (X ∈ `+ - * / % & | ^`) и — через новый
`является_трёхсимвольным_оператором` + жадную 3-символьную ветку в цикле — `<<=`/`>>=`
(раньше `<<=` распадался на `<<`+`=`). Сравнения `== != <= >=` под правило не
подпадают (у них `начало[0] ∈ = ! < >`).

**Парсер** (`разобрать_выражение_или_присваивание`). Базовый оператор = токен без
хвостового `=` (`тип_базового_оператора`); левый операнд биноп — `узел_копировать(цель)`
(независимая копия → нет double-free), правый — RHS. Узел: `ПРИСВАИВАНИЕ(цель, БИНОП)`.

**Double-fetch/TOCTOU — закрыт по построению.** Цель эмитится ДВАЖДЫ (в присваивании
и в биноп-копии), поэтому её оценка обязана быть без побочных эффектов. Парсер
ОТВЕРГАЕТ цель, содержащую вызов (`узел_содержит_вызов`): `с[f()] += 1` → ошибка
(«присвойте во временную»). Прочие цели (переменная, `с[i]` с простым индексом, поле,
цепочка) side-effect-free → двойная оценка идентична (для среза — двойная
проверка границ; корректно, лишь микро-цена; в каноническом цикле BCE её элидирует).

**Семантика — как у `цель = цель ОП значение`** (сознательно): `целое8 x; x += 20`
даёт ту же ошибку сужения, что и `x = x + 20` (литерал `20` — `целое32`); работает
`x += как<целое8>(20)` или `x += другой_целое8`. Не спецкейсим — единообразие с
языком. Тесты: `составное_все` (10 операторов = 15), `_срез` (+ шаг `i += 1` как
канонический цикл), `_поле`, `_деление_ноль` (abort через guard), `_беззнак`
(`1<<63`), `_перегрузка` (структуры), негативы `_вызов_в_цели`/`_конст`.

**Не покрыто:** унарные `++`/`--` (лексер их токенизирует, но синтаксиса нет —
отдельный слайс); цель с побочным эффектом (сознательно запрещена).

## §46. «цикл { }» (Rust `loop`) + CLI «--код=<исходник>» (исходник аргументом)

Два запроса пользователя одним срезом: (1) бесконечный цикл «без всего, как
`loop` в Rust»; (2) транслятор принимает исходник строкой-аргументом, чтобы
ускорить тесты — не создавать временный файл под каждый мелкий кейс (меньше I/O).

**`цикл { … }` — бесконечный цикл.** Контекстное слово (НЕ ключевое — по принципу
«новое слово не отнимает имя у программиста»): распознаётся только как
идентификатор `цикл`, за которым (через возможные переводы строк) идёт `{`; иначе
`цикл` — обычное имя переменной (`целое32 цикл = 0` работает). Реализация —
**чистый десугар в парсере**: `цикл { тело }` → `пока истина { тело }` (узел
`УЗЕЛ_ПОКА` с синтетическим условием `истина`). Переиспользуется ВСЯ машинерия
`пока`: `прервать`/`продолжить`, кодоген (`while (true)`), и — важно —
**анализ дивергенции**. Как в Rust: `цикл` без `прервать`, с выходом только через
`вернуть` внутри, СЧИТАЕТСЯ расходящимся (возврат после него не нужен —
`первый_чётный` компилируется); `цикл` с `прервать` — НЕ расходящийся (управление
падает за цикл → non-void функции нужен возврат после, ошибка all-paths). Это
свойство уже было у `пока истина` — десугар получил его бесплатно. Ноль правок
семантики/кодогена. Тесты `цикл_база`/`_дивергенция`/`_имя`/`_прервать_нужен_возврат`.

**CLI `--код=<исходник>` (`--code`, `-e <исходник>`).** Исходник передаётся
строкой-аргументом; транслятор кладёт его в собственный буфер (токены держат
указатели внутрь — как для файла) вместо `прочитать_файл`. Имя вывода — `--имя=`
(`--name=`, по умолчанию `код`) → `вывод/<имя>.c`/`.elf`; каталог базы для
локальных `#содержит` — `.`. **v1-ограничения:** один синтетический «файл»
(мультифайл только через реальные файлы); `--код` + файловый аргумент — ошибка
(неоднозначно, чем является программа). Всё остальное (`--только-си`, `--релиз`,
stdlib и т.д.) применяется как обычно. Экономия: пропадает запись временного
`.конда` (одна запись + одно чтение на кейс); `.c`/`.elf` по-прежнему пишутся —
их требует внешний `cc`. Тесты `--код`/`-e`/`--имя`/guard-«код+файл».

## §47. Постфиксный инкремент/декремент «x++» / «x--» (Go-стиль оператор)

Запрос пользователя (унарные операторы). Развилки — через AskUserQuestion; ответы:
- **Статус: только ОПЕРАТОР** (Go-стиль), не выражение. «x++»/«x--» — самостоятельная
  строка, значение не используется. `y = x++`, `arr[i++]`, `f(x++)` — синтакс-ошибка
  (нет побочных эффектов в подвыражениях — дух языка, где выражения почти чисты).
- **Форма: только postfix** «x++».
- **Побочные эффекты цели: разрешить, хойстить адрес** — «с[f()]++» вызывает f() один раз.

**Почему отдельный узел, а не десугар в «x = x + 1» (как §45).** Десугар упёрся бы в
запрет сужения: «целое8 x; x++» → «x = x + 1», где «целое8 + 1» → «целое32» (литерал
1 — целое32), затем «x = целое32» — ошибка сужения. Ломало бы «++» на ЛЮБОМ малом
целом. Отдельный `УЗЕЛ_ИНКРЕМЕНТ` эмитит НАТИВНЫЙ C `(цель)++` — правило сужения не
возникает вовсе.

**Single-eval — БЕСПЛАТНО от C.** Нативный `(цель)++` вычисляет lvalue РОВНО ОДИН
РАЗ (гарантия C), поэтому «с[f()]++» → `(*(int32_t*)срез_доступ(с, f(), …))++` зовёт
f() один раз — хойст, которого просил пользователь, даёт сам C.

**Отладка + знаковое целое → guard переполнения.** `-fwrapv` снят в отладке (только
релиз), поэтому «INT_MAX++» без guard — UB. Эмитим хойст-форму с `арифметика_безопасно`
(реюз §43-хелпера): `({ typeof(цель) *_кц = &(цель); *_кц = арифметика_безопасно(
(long)(*_кц), (long)(1), ОП, ширина, строка); })` — адрес взят один раз (typeof —
невычисляемый контекст), abort при +1 у МАКС / −1 у МИН. Беззнаковое (перенос
определён), вещественное, релиз — нативно. Триггер пролога: `узел_использует_guard_
бинопа` ослаблен до `проверка_бинопа == вид` для любого узла (не только БИНОП).

**Типы.** Целое / вещественное / указатель. Указатель++ = арифметика указателя →
только в «небезопасно». Логический/структура/срез — ошибка «неприменим».

**Безопасность — критично (класс §43 Ф1).** Мутацию через «++» ОБЯЗАНЫ видеть
анализы, снимающие проверки: `имя_изменяется_в` (лишний «и++» в теле канонического
цикла отменяет элизию границ — иначе индекс прыгал бы за длину, выход за границы),
`собрать_изменяемые` (не считать «++»-переменную известной константой),
`искать_прямой_эффект` (нечистота: «срез_парам[i]++» — запись в срез вызывающего),
`проверить_параллельное_тело` («счёт++» на внешней переменной в «параллельно для» —
гонка). Шаг «и++» распознаётся как канонический (`распознать_безопасный_цикл`, шаг +1;
«и--» — нет, убывающий не канон). Диспетчер операторов (`анализ_оператора`,
`кодоген_оператора`) получил ветку УЗЕЛ_ИНКРЕМЕНТ (иначе оператор молча пропадал).

Тесты `инкремент_*`: основы (в т.ч. целое8 без приведения), переполнение (abort),
срез+цикл i++ (BCE), single-eval «с[f()]++», BCE-тело (лишний и++), негативы
конст/нечисло/параллельно, `y = x++` (выражение — ошибка). Полный run.sh + оба
санитайзер-свипа — чисто.

**Не покрыто:** prefix «++x» (выбрана только postfix-форма); «++»/«--» как выражение.

## §48. Релиз-флаги: `-fno-math-errno` и `-fno-plt` (снятие искусственных барьеров)

Часть плана микро-оптимизаций сгенерированного C-кода (см. `logical-seeking-bee.md`). Два
флага, включённые ТОЛЬКО в релизе, снимают искусственные барьеры оптимизатора и не
нарушают инвариант №1 (это не проверки, а разрешения оптимизации — рантайм не растёт).

**`-fno-math-errno`.** По стандарту C `sqrt/exp/log/pow/...` ставят `errno` при доменной
ошибке (`sqrt(-1)`→`EDOM`). Компилятор обязан считать это побочным эффектом → не может
векторизовать и всегда зовёт через реальный call. Флаг снимает это (стандарт C
явно разрешает); gcc/clang сам инлайнят математику в SIMD. НЕ в отладку — там errno-
семантика полезна для диагностики.

**`-fno-plt`.** Каждый вызов libc/jemalloc/pthread идёт через PLT-thunk (косвенный прыжок +
`bnd`-байт + запись в `.got.plt` при первом вызове). С `-fno-plt` gcc эмитит прямой
indirect через GOT (`call *printf@GOTPCREL(%rip)`) — минус инструкция на каждый внешний
вызов. Полностью совместимо с §28 FULL RELRO: `-Wl,-z,now` уже ставится, ленивого
разрешения нет, оверхед PLT-thunk бесполезен.

**Отладка не тронута** (проверено тестом `флаги_сборки`): в дефолтной сборке этих флагов
нет. Инвариант №1 цел на обеих ветках.

Тест: `флаги_сборки` расширен четырьмя проверками (наличие в релизе, отсутствие в отладке).
Полный run.sh + оба санитайзер-свипа — чисто.
