# План: система сборки Konda (`konda build` + манифест TOML)

**Статус: 🟢 РАБОТАЕТ (v1).** Цель — удобная сборка: манифест вместо портянки
CLI-флагов, мультифайл, воспроизводимость. Приоритет P0 (таблица пропусков языка —
в истории обсуждения). **Стандартная библиотека Konda собирается ИМЕННО этой
системой** (`stdlib/Konda.toml`, цель `stdlib` в корневом `Makefile`) — крупнейший
реальный потребитель фронтенда (монолитная библиотека из 4 модулей).

## Принятые решения (пользователь)

1. **Формат манифеста — TOML** (`Konda.toml`). Знакомый, декларативный.
2. **Парсер TOML пишем НА KONDA** и собираем в `.so`-библиотеку (`--библиотека`).
   Дожфудинг: реальная нетривиальная библиотека на языке → вскрывает пробелы
   stdlib (строки), проверяет `.и`-интерфейс/линковку.

## Ограничения языка, влияющие на дизайн (проверено спайком)

- **Возврат borrow-параметра — ошибка** (§37 п.6): функция НЕ может вернуть
  `срез<символ>`-вид внутрь параметра-текста. → API отдаёт **offsets (POD-структуру
  `Диапазон{начало,длина,есть}`)**, а срез строит вызывающий: `текст[д.начало :
  д.начало+д.длина]`. Обходит ограничение без рантайм-цены.
- **`буфер<структура>` — v1 только примитивы/указатели** (§59); **`срез<структура с
  владеющими полями>`** требует §61-деструкции, а borrow-поля-срезы туда не
  ложатся. → Парсер **не строит дерево/контейнер**: он **query-based** — каждая
  функция сканирует текст заново (манифест мал, O(n·k) незаметно). Ноль
  динамических контейнеров → чистый v1 без упора в лимиты.
- **Возврат структурного литерала напрямую** (`вернуть Имя {…}`) не парсится →
  собираем в переменную, потом `вернуть`.
- Строки: `==`/конкатенации нет, но `символ`-сравнение, `s[a:b]`, `длина`, `вкси`
  есть — их достаточно для сканера.

## Библиотека `libkonda_toml` (query-API, offsets, 0 контейнеров)

Файл: `toml/toml.конда` → `toml/вывод/toml.so` + `.и` (собирается транспилятором
после его сборки; бутстрап: transpiler(C) → toml.so(Konda)).

```
структура Диапазон { целое32 начало; целое32 длина; логический есть }

// [секция] пусто = верхний уровень. Возвращают offsets в «текст».
Диапазон томл_значение(текст, секция, ключ)      // сырое значение до конца строки
Диапазон томл_строка (текст, секция, ключ)       // значение-строка без кавычек
целое32  томл_флаг   (текст, секция, ключ, умолчание)// да/true→1, нет/false→0
целое32  томл_длина_списка(текст, секция, ключ)  // ["a","b"] → 2
Диапазон томл_элемент(текст, секция, ключ, индекс)// i-й элемент массива (без кавычек)
```

Имена — БЕЗ сокращений (полные слова): `томл_длина_списка`, `пропустить_пробелы`,
`значение_конец` и т.п. (правило проекта, см. CLAUDE.md).

Подмножество TOML (полного не нужно для манифеста; расширение ждёт string-stdlib):
- секции `[имя]`, пары `ключ = значение`;
- комментарии `#` — **целой строкой И в конце строки-значения** (inline);
- строки `"..."`, булевы `true/false` (+ рус. `да/нет`);
- массивы строк `["a", "b"]` — **в т.ч. многострочные** (до парной `]`).
- НЕ поддержано (позже): целые/дробные (нужен каст `символ→целое`, см. ниже),
  вложенные/dotted-ключи, inline-таблицы, arrays-of-tables, multiline/литеральные
  строки, escape внутри строк, даты.

**Дожфудинг-находка:** `томл_целое` не реализуемо сейчас — `символ→целое` в языке
не выражается (§31: `символ` неарифметичен, `как` его не берёт). Манифесту целые
не нужны (версия — строка). Кандидат в язык/stdlib: явный каст `символ→целое`.

## Манифест `Konda.toml` (схема)

```toml
[проект]
имя       = "конда_init"
версия    = "0.1.0"
тип       = "программа"        # программа | библиотека
исходники = ["основа.конда", "утилиты.конда"]  # НЕОБЯЗАТЕЛЬНО (см. авто-скан ниже)
исключить = ["пример.конда"]   # при авто-скане: не-исходники (примеры и т.п.)
выход     = "init"

[сборка]
цель       = "x86_64-linux"    # триплет; пусто → хост
режим      = "релиз"           # дебаг | релиз
аллокатор  = "jemalloc"        # jemalloc | libc
статический= false
стдлиб     = true
флаги      = ["--без-символов"] # доп. сырые флаги транспилятора
embed-dir  = "."
зависимости= ["../СтандартнаяБиблиотекаКонда"]  # пути к Konda-проектам/.и
```

## Авто-скан источников (`[проект].исходники` необязателен) — ✅ СДЕЛАНО (§95)

Как в Cargo/Rust: **исходники можно не перечислять**. Логика фронтенда:

- `[проект].исходники` **задан** (непустой массив) → берётся как есть, в порядке
  манифеста (для монолитной библиотеки §80 порядок важен — так собирается stdlib).
- `[проект].исходники` **пуст/отсутствует** → фронтенд **сканирует каталог проекта**
  (CWD, где лежит `Konda.toml`) на `*.конда` и берёт их **отсортированно**
  (`scandir`+`alphasort` — детерминированный порядок → стабильный ключ хеш-кэша).
  Не-исходники (примеры со своей `точка_входа`, вспомогательные `.конда`) убираются
  полем **`[проект].исключить = ["имя.конда", …]`** (чёрный список имён файлов).
  Подкаталоги (в т.ч. `вывод/`) в скан не попадают — у них нет суффикса `.конда`.

Имя выхода при авто-скане: `[проект].имя` (или `выход`), а если не заданы — базовое
имя ПЕРВОГО источника (то же правило, что у транспилятора без `--имя`). Пустой
каталог без `.конда` → понятная ошибка «нет источников».

Реализация — стор источников в C-шиме (`сборка_сканировать_исходники` и др.),
Konda-слой наполняет его и берёт пути по индексу как `символ*` (единый путь для
явного списка и авто-скана). Детали и обоснование (в т.ч. почему источники —
`символ*`, а не `внешняя срез`) — в `docs/РЕШЕНИЯ.md §95`.

## Фронтенд `konda build` — ✅ СДЕЛАН (вариант B)

Реализован **вариант B**: отдельный Konda-бинарь `сборка/сборка.конда`, потребляет
`libkonda_toml` через `.и` (§34), запускает транспилятор через тонкий C-шим
`сборка/сборка_шим.h` (чтение файла + `fork`+`execvp`). Собирается `сборка/собрать.sh`,
e2e-тест `сборка/тесты.sh` (демо `сборка/пример/`).

Что делает: читает `Konda.toml` (аргумент или из CWD), берёт `[проект].исходники`,
`[проект].тип`, `[проект].имя`, `[проект].версия`, `[проект].выход`,
`[сборка].режим/статический/стдлиб/аллокатор/флаги/цели/зависимости`;
собирает хвост команды (`--релиз`/`--библиотека`/`--статический`/
`--без-стандартной-библиотеки`/`--аллокатор=`/**`--имя=`**/**`--версия-проекта=`**/
доп. `флаги` + список источников) и запускает транспилятор. **`[проект].имя`**
пробрасывается как **`--имя=`** — базовое имя выходных артефактов; для монолитной
библиотеки из нескольких источников (как stdlib) это ЕДИНСТВЕННЫЙ способ назвать
`.so/.и/.h`, иначе транспилятор назвал бы её по первому источнику.
**`[проект].версия`** (§89) пробрасывается
как `--версия-проекта=` → вшивается в ELF (символ `КОНДА_ВЕРСИЯ`, нота
`.note.konda`, запись `.comment`); проверяется e2e-тестом. Независимо транспилятор
всегда штампует «транслировано Konda + версия транспилятора». Прикладной сахар булевых (`да`/`нет`) — здесь
(`флаг_манифеста`), не в TOML-библиотеке (та spec-faithful: `true`/`false`).

**Находки (без правки транспилятора):**
- Потребление внешней Konda-библиотеки — через `#содержит "путь/toml.h"`:
  транспилятор находит рядом `toml.и` (интерфейс) и `toml.so` (линкует, rpath).
- **DT_NEEDED пишется тем же путём, что дан на линковке.** Если путь к `.so`
  относительный (относителен CWD запуска) — бинарь не найдёт библиотеку из другого
  каталога. Обход: собирать фронтенд по **абсолютному** пути источника → путь к
  `.so` абсолютный → находится отовсюду. (Кандидат на будущее: `-Wl,-soname` у
  `--библиотека`, чтобы NEEDED был по soname + rpath.)
- Путь транспилятора фронтенд берёт из `KONDA_TRANSPILER` (иначе `PATH`).
- Запуск через `fork`+`execvp` с argv (`буфер<символ*>` в Konda → `срез<символ*>`
  в шим, шим ставит `argv[0]`=транспилятор): **без shell**, поэтому пути и
  аргументы с пробелами/спецсимволами передаются дословно (проверено на источнике
  «мой модуль.конда»). Комбинированные argv-элементы (`--аллокатор=<v>`,
  `--вывод=вывод/<триплет>`, копии путей-срезов) склеивает шим `сборка_склеить`
  (heap-строки, утечка намеренна — процесс вскоре exec/выйдет).

Проброшены: `тип`, `имя`, `версия`, `выход`, `режим`, `статический`, `стдлиб`,
`аллокатор`, `флаги`, `цели`, `зависимости`. Ограничения v1: источники
относительны CWD запуска; `embed-dir` (`--embed-dir=`) пока не пробрасывается
(единственное оставшееся поле схемы).

## Защита от устаревания — хеш-кэш ✅ СДЕЛАНО

`konda build` хранит **ключ актуальности** в `.konda-сборка.кэш` (в каталоге
запуска). Ключ = FNV-1a-хеш от: команды (флаги + имена источников) + содержимого
манифеста + содержимого КАЖДОГО источника + бинаря транспилятора. Если ключ
совпал с сохранённым — сборка пропускается («актуально — пересборка не нужна»).
`--пересобрать` игнорирует кэш.

Почему по **хешу содержимого**, а не по mtime (как make): устойчиво к
`git checkout`/`touch`/clock skew; и, в отличие от make, **видит смену флагов**
(флаги входят в ключ) → не выдаёт бинарь, собранный со старыми флагами. Бинарь
устареть не может: любой изменённый вход меняет ключ.

Всё хеширование — в C-шиме (`сборка_шим.h`): байтовая арифметика и беззнаковое
переполнение с переносом не выражаются в Konda (`символ` неарифметичен §31,
знаковый `целое64`-overflow в отладке падает по guard). Konda лишь передаёт данные
и сравнивает готовые `целое64`-ключи. Тест — в `сборка/тесты.sh` (повтор пропускает,
`--пересобрать` форсит, смена флага манифеста вызывает пересборку).

**Зависимости — `зависимости` в `[сборка]`**: список каталогов проектов; фронтенд
собирает каждый ПЕРЕД целью (запускает СЕБЯ в каталоге зависимости —
fork+chdir+exec `/proc/self/exe`). У каждой зависимости свой `Konda.toml` и свой
кэш → **пер-проектный инкремент** (это и есть «инкремент для зависимостей»).

**Кросс-платформенность — `цели` в `[сборка]`** (массив триплетов): по сборке на
цель, каждая в `вывод/<триплет>` со своим кэшем; `хост` = нативная. Использует уже
поддержанный тип (массив строк) — без вложенных таблиц TOML.

## Параллелизм `-j` ✅ СДЕЛАНО

`konda build [-jN | --задания=N]` собирает **цели** и **зависимости** параллельно
(пул процессов с ограничением одновременных заданий N). Значения: `-jN`/`-j N`/
`--задания=N` — N заданий; `-j`/`--задания` без числа — число ядер (авто); без
флага — **1** (последовательно, поведение как раньше — байт-в-байт, тесты `-j1`
не трогаются). `-j` пробрасывается в под-сборки зависимостей (транзитивный
параллелизм).

Модель — **процессная, как `make -j`** (fork+exec), не data-parallel: `параллельно
для` не подходит (он запрещает нечистые вызовы; запуск процесса нечист). Поэтому
инвариант «нет гонок данных» цел по построению — разделяемого изменяемого
состояния в Konda не появляется, синхронизация на уровне ОС. Оркестрация — в
`сборка.конда` (`собрать_цели_параллельно`/`собрать_зависимости_параллельно`:
троттлинг по счётчику живых потомков + дренаж); syscall-примитивы — в шиме
(`сборка_форкнуть`/`сборка_выход`/`сборка_ждать_любого`/
`сборка_запустить_зависимость_нежд`). Неудача `fork` → синхронный fallback (задание
не теряется). Разбор `-j` — в шиме (`сборка_число_из`/`сборка_это_число`/
`сборка_число_ядер`): целочисленный разбор строк в Konda не выражается (§31).

**Корректность:**
- **Цели независимы** — каждая пишет в свой `вывод/<триплет>` со своим кэшем →
  гонок по выходным файлам нет. Каждая цель — потомок, выполняющий `собрать_цель`
  и завершающийся `сборка_выход` (в цикл раздачи заданий не возвращается).
- **Зависимости — ромб** (общая под-зависимость собирается из двух мест
  одновременно) закрыт **межпроцессной блокировкой каталога**
  (`сборка_взять_блокировку`: `flock(LOCK_EX)` на `./.konda-сборка.lock`, берётся
  в начале каждой сборки, держится до выхода). Второй сборщик того же каталога
  ждёт на блокировке, затем видит кэш актуальным и не пересобирает. Граф
  зависимостей — DAG, блокировки берутся по разным каталогам вниз по дереву →
  взаимоблокировок нет. Файл `.konda-сборка.lock` — в `.gitignore`.

Тесты — `сборка/тесты.sh`: параллельные зависимости под `-j4`; ромб под `-j8`
(общая собрана без гонки); две цели (`хост` + `x86_64-linux-gnu`, если есть кросс-
gcc) в раздельные каталоги; паритет `-j2` с последовательной сборкой демо.
