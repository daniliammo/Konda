# Типизированные слушатели (`слушатель<T>` + доверенный трамплин)

**Статус: ДИЗАЙН (код не написан).** Решение пользователя — зафиксировать полную
схему listener-структур, реализацию отложить отдельным заходом.

Цель — сделать безопасным доминирующий блокер конвертации GUI-кода: колбэк с
`void *data`, который в теле кастуется к типу (`struct T *t = data`). На клиентах
weston это ~68 % всего небезопасного/непереводимого (см.
`../../../Документы/weston/конда-клиенты/СВОДКА.md`). Механически безопасно это не
переводится (каст `void*→T` недоказуем), но **языковая фича с генерацией
трамплина** снимает проблему по построению.

## 1. Проблема

Вейланд-паттерн (и toytoolkit `widget_set_*_handler`) в C:

```c
struct wl_registry_listener {                 /* СТРУКТУРА колбэков */
    void (*global)(void *data, struct wl_registry *r,
                   uint32_t name, const char *iface, uint32_t ver);
    void (*global_remove)(void *data, struct wl_registry *r, uint32_t name);
};
int wl_registry_add_listener(struct wl_registry *r,
                             const struct wl_registry_listener *l, void *data);

static void handle_global(void *data, struct wl_registry *r, uint32_t name, …) {
    struct display *d = data;                 /* ← НЕДОКАЗУЕМЫЙ каст void*→T */
    …используем d, r, name…
}
static const struct wl_registry_listener reg_l = {
    .global = handle_global, .global_remove = handle_global_remove,
};
wl_registry_add_listener(registry, &reg_l, display);  /* display: struct display* */
```

`data` во всех колбэках одного слушателя — ОДИН и тот же указатель (`display`),
переданный при регистрации. Тип `T` (= `display`) фиксирован на слушатель.

## 2. Дизайн

### 2.1. Идея

Konda **сама генерирует трамплин** — маленькую C-функцию, где каст `void*→T`
спрятан в ОДНОМ месте и привязан к типу `T`, заявленному при регистрации:

```c
/* генерируется транспилятором */
static void _трамп_handle_global(void *data, struct wl_registry *r,
                                 uint32_t name, const char *iface, uint32_t ver) {
    handle_global((display *)data, r, name, iface, ver);   /* T известен статически */
}
```

Пользователь пишет колбэк **типизированно** — без `void*` и без каста:

```конда
ничего handle_global(изменяемый Дисплей д, wl_registry* р,
                     целое32 имя, символ* интерфейс, целое32 версия)
{
    … используем д.поле, р, имя …          // д — ссылка на Дисплей, разыменование безопасно
}
```

### 2.2. Синтаксис (по образцу `внешняя`/`типфункции`/`поток`)

Три конструкции, все контекстные (не отнимают имён):

**(1) Тип слушателя** — привязка к внешнему C-listener-типу + userdata-типу `T`.
Поля — сигнатуры колбэков БЕЗ `void*data` (его добавит трамплин), первый
логический параметр — `изменяемый T`/`чтение T`:

```конда
внешний слушатель<Дисплей> РеестрСлушатель для wl_registry_listener {
    global(изменяемый Дисплей д, wl_registry* р, целое32 имя, символ* интерфейс, целое32 версия)
    global_remove(изменяемый Дисплей д, wl_registry* р, целое32 имя)
}
```
- `для wl_registry_listener` — имя C-типа (кодоген печатает `struct
  wl_registry_listener` в литерале). Как `внешний тип` — непрозрачный, by pointer.
- Порядок и имена полей ДОЛЖНЫ совпадать с C-структурой (кодоген заполняет
  designated-инициализаторы `.global = _трамп_…`).

**(2) Экземпляр слушателя** — связывает поля с конкретными колбэк-функциями:

```конда
РеестрСлушатель реестр_л = {
    global = handle_global,
    global_remove = handle_global_remove,
}
```
Семантика проверяет: сигнатура каждой функции совпадает с полем (тип `T`,
остальные параметры — с C-сигнатурой). Как проверка имени функции для
`типфункции`-параметра (уже есть).

**(3) Регистрация** — `слушать(add_listener, объект, экземпляр, данные)`:

```конда
слушать(wl_registry_add_listener, реестр, реестр_л, дисплей)
```
- `wl_registry_add_listener` — внешняя C-функция `(объект*, listener*, void*)`.
- `дисплей` — типизированные данные типа `Дисплей` (или `Дисплей*`); их тип
  ОБЯЗАН совпадать с `T` типа слушателя. Кодоген передаёт `(void*)&дисплей` (или
  `дисплей`, если это уже указатель).

### 2.3. Кодоген (по образцу шимов потоков `кодоген_шимов_потоков`)

На каждый ЭКЗЕМПЛЯР слушателя транспилятор эмитит:
1. **Трамплин на каждое поле** — C-функция с реальной C-сигнатурой (`void*data`
   + прочие), внутри — каст `(T*)data` и вызов типизированного колбэка. Это
   ровно та же техника, что генерируемый `_запуск_ф` у потоков (Konda-функция,
   обёрнутая сгенерированным C).
2. **C-структуру-литерал** `static const struct wl_registry_listener _л_реестр_л
   = { .global = _трамп_handle_global, … };`.
3. На `слушать(...)` — вызов `wl_registry_add_listener(реестр, &_л_реестр_л,
   (void*)&дисплей)`.

Колбэк-функции печатаются как обычные Konda-функции, но их первый параметр
`изменяемый Дисплей` в C становится `Дисплей*` — что СОВПАДАЕТ с тем, что
трамплин передаёт (`(Дисплей*)data`). Никакого `void*` в пользовательском коде.

### 2.4. Почему безопасно по построению

- **Тип-безопасность (решается полностью).** Каст `void*→T` существует в ЕДИНСТВЕННОМ
  месте — сгенерированном трамплине, и `T` там не «доверенное предположение», а
  тип, заявленный в типе слушателя И проверенный на месте `слушать` (тип `данные`
  == `T`). Пользователь не пишет ни `void*`, ни каст. Это не `небезопасно` с
  честным маркером, а именно доказанная связка «зарегистрировали `&данные:T` →
  получили `T*`».
- **Нет сырого `void*` в теле** → тела колбэков перестают быть `небезопасно`
  целиком (сейчас именно `struct T *t = data` заворачивает всю функцию).

### 2.5. Открытый вопрос безопасности: ВРЕМЯ ЖИЗНИ `данные` (фаза 2)

Колбэк срабатывает ПОЗЖЕ, чем возвращается регистрирующая функция, поэтому
`данные` обязаны пережить регистрацию слушателя. Тип-безопасность это не
покрывает. Варианты (решить в реализации):
- **(а)** `слушать` требует `владеет`-передачи `данные` в слушатель — слушатель
  становится владельцем, освобождает при снятии/выходе (RAII, как autofree
  среза/join потока). Самый безопасный; но снятие слушателя вейланд делает не
  всегда явно.
- **(б)** Требовать, чтобы `данные` были объектом со статической/кучной
  длительностью, доказанно переживающим слушатель (аналог borrow-провенанса
  `безопасен_для_возврата` — но здесь наоборот, «переживёт-долго»).
- **(в)** Принять как задокументированное обязательство пользователя (частичная
  безопасность: тип решён, время жизни — на программисте). Наименее строго, но
  уже строго лучше сырого `void*`.

Рекомендация: фаза 1 — тип-безопасность (трамплины, вариант «в» по времени
жизни); фаза 2 — RAII-владение данными (вариант «а»), когда появится модель
снятия слушателя.

## 3. Что это даёт конвертеру kfc

kfc сможет РАСПОЗНАТЬ идиому и переписать в `слушать`:
- находит `X_add_listener(obj, &listener_var, data)` (уже частично умеет —
  типизация `void*`-позиции);
- по `listener_var` (struct-литерал) собирает поля → колбэк-функции;
- по каждому колбэку: первый `void *data` + `struct T *x = data` → тип `T`;
- эмитит тип слушателя + экземпляр + `слушать`, а тела колбэков — с
  `изменяемый T` вместо `void*` (каст и `x = data` убираются подстановкой,
  `x` → `данные`).

Это снимает ДВА кластера разом: тела колбэков (~490 `небезопасно`) и часть
`адрес-оф`, транзитивно отравленную `void*`. Оценка — крупнейший единичный
сдвиг из оставшихся ~985 пометок.

## 4. Инварианты (не нарушаются)

- **№1 (нулевая рантайм-цена):** трамплин — прямой вызов, инлайнится; C-структура
  статическая; никакого рантайма/раскрутки. Как шимы потоков.
- **№2 (`небезопасно` только явно):** каст `void*→T` уходит в сгенерированный
  код, помеченный доверенным по построению — пользовательского `небезопасно` нет.
- **Нет borrow-checker:** тип-безопасность даётся связыванием на месте `слушать`,
  не анализом времён жизни. Время жизни `данные` — отдельная фаза (см. §2.5), и
  её строгий вариант — RAII-владение, а не borrow-checker.

## 5. Фазы реализации

1. **Лексер/парсер:** контекстные `слушатель`/`для`/`слушать`; разбор типа
   слушателя (поля-сигнатуры), экземпляра (поле=функция), вызова `слушать`.
2. **Семантика:** тип слушателя → таблица; проверка сигнатур колбэков против
   полей; на `слушать` — сверка типа `данные` с `T`; отметить колбэк-функции,
   чтобы их первый параметр печатался как `T*`, а тело не требовало `небезопасно`.
3. **Кодоген:** пред-проход, эмитящий трамплины + C-структуру-литерал (образец —
   `кодоген_шимов_потоков` в `кодоген.c`); `слушать` → вызов add_listener.
4. **IDE-hover, тесты (`tests/run.sh`), README, этот док → «реализовано».**
5. **Фаза 2:** RAII-владение `данные` (§2.5, вариант «а»).
6. **kfc:** распознавание идиомы (§3) — отдельно, после языковой фичи.
