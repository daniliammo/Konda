# План: сигналы и события в языке (нативный pub/sub)

**Статус: 🟡 ПРЕДЛОЖЕНИЕ (не реализовано).** Маленький план фичи «удобные
сигналы/события». Отталкивается от §13/§68 (типизированные слушатели) и держит
инварианты Konda.

## Зачем (и чем отличается от слушателей §13)

Типизированный **слушатель** (§13/§68) — это МОСТ к СУЩЕСТВУЮЩЕМУ C-API колбэков
(`X_add_listener(obj, &структура_колбэков, данные)`): он прячет каст `void*→T` в
трампулине. Он не про то, чтобы *объявить своё событие* в Konda-программе.

**Сигнал/событие** — НАТИВНАЯ конструкция: объявить событие внутри Konda-кода,
подписать на него обработчики, «излучить». Это доминирующий паттерн GUI-виджетов,
конечных автоматов, pub/sub между модулями — сейчас его пишут вручную (массив
указателей на функции + цикл вызова), что тянет сырой `void*`/`небезопасно`.

## Инвариантная развилка (и как её снять)

Событие по природе хранит СПИСОК подписчиков — изменяемое состояние. Это давит на:
- **№4 (нет разделяемых изменяемых глобалов / гонок данных):** список нельзя
  делать глобалом. → Событие либо **compile-time-связанное** (списка в рантайме
  нет вовсе), либо **владеющий объект** (single-owner, как `буфер`/`Ящик`, мутация
  только через `изменяемый`/методы — не глобал, не сырой `&`).
- **№1 (нулевая рантайм-цена в релизе):** динамический список + косвенный вызов —
  это цена. → Разносим на два уровня: zero-cost ядро (v1) и opt-in рантайм (позже).

## Уровень 1 (v1) — статически-связанные события. НУЛЕВАЯ цена.

Подписки известны на компиляции; `излучить` десугарится в ПРЯМЫЕ вызовы. Списка,
кучи, косвенного вызова — нет. Как compile-time multicast. Полностью статично,
memory-safe, без глобалов (проводка — факт кодогена, не рантайм-объект).

```конда
событие Клик(целое32 x, целое32 y)      // объявление: имя + payload-сигнатура

при Клик обработать_клик                 // статическая подписка (compile-time)
при Клик логировать_клик

// … где-то в коде:
излучить Клик(10, 20)
```
десугар (в парсере/кодогене, как `цикл`§46/range-for§67 — 0 правок семантики):
```c
обработать_клик(10, 20);
логировать_клик(10, 20);
```
- Обработчики — обычные типизированные Konda-функции (никакого `void*`/каста/
  `небезопасно`). Сигнатура сверяется с `событие` (как поле слушателя §13).
- `событие`/`при`/`излучить` — **контекстные** слова (имён не отнимают: как
  `в`/`по`§67, `цикл`§46, `асм`§60).
- Порядок вызова — порядок объявления `при` (детерминирован).
- Инварианты целы: №1 (десугар в прямые вызовы), №4 (нет рантайм-состояния),
  «нет сырого `&`» (обработчик зовётся по имени). Payload — как аргументы вызова
  (примитивы/структуры-по-значению/`изменяемый`-проекция общего приёмника).

**Этого достаточно** для статических графов событий (виджет всегда шлёт в фикс-
набор обработчиков) и это правильный первый вертикальный срез (§6 — но без
динамики, т.к. динамика ТРЕБУЕТ рантайма → это смена уровня, а не урезание v1).

## Уровень 2 (позже, opt-in рантайм) — динамические сигналы `сигнал<Args>`

Когда набор подписчиков меняется в рантайме (подписка/отписка по ходу):
```конда
сигнал<целое32, целое32> клик = создать()
подключить(клик, обработать_клик)        // рантайм-connect
излучить(клик, 10, 20)                    // цикл по подписчикам
отключить(клик, обработать_клик)
```
- **Владеющий объект** (single-owner, autofree — переиспользует `буфер<T>` §59 для
  растущего списка обработчиков; на C — тот же `Срез`+ёмкость). Не глобал → №4 цел.
- Хранение payload-данных подписчика — через трампулины §13 и RAII-владение §68
  (время жизни данных = вариант «а»).
- **Цена НЕнулевая** (список + косвенный вызов) → это осознанный opt-in Tier 2,
  как каналы/async в `ПЛАН_ПАРАЛЛЕЛИЗМА.md`: включаешь, когда реально нужна
  динамика. Не подрывает №1: статический путь (Tier 1) остаётся zero-cost.
- Потоки: `сигнал` — владеющий объект передачи-владения (как `буфер`); излучение
  из `параллельно для` запрещено (мутация общего списка = гонка) — ловится
  существующим анализом чистоты.

## Фазы реализации (Tier 1)

1. **Лексер/парсер:** контекстные `событие`/`при`/`излучить`; узлы
   `УЗЕЛ_СОБЫТИЕ` (имя + сигнатура payload), `УЗЕЛ_ПОДПИСКА` (`при E fn`),
   `УЗЕЛ_ИЗЛУЧИТЬ` (`излучить E(args)`). Собрать таблицу событие→[обработчики] за
   пред-проход (как cross-file обобщения §18 — по всем файлам до кодогена).
2. **Семантика:** сверка сигнатуры каждого `при`-обработчика с payload события
   (как проверка колбэка слушателя §13); `излучить` — проверка типов аргументов
   против сигнатуры; неизвестное событие/несовпадение — ошибка с позицией.
3. **Кодоген:** `излучить E(args)` → последовательность прямых вызовов
   обработчиков (в порядке `при`). Ноль рантайм-структур.
4. **IDE-hover, тесты `run.sh`, README + `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md`.**

## Открытые вопросы (решить при реализации)

- **Область события.** Верхний уровень (глобальное имя события — но проводка
  compile-time, не состояние) против события-члена структуры (виджет-локальное).
  v1 — верхний уровень (проще; №4 не задет, т.к. рантайм-состояния нет).
- **`излучить` до всех `при`?** Пред-проход собирает подписки по всем файлам →
  порядок «объявления» стабилен; multi-file — как cross-file generics.
- **Возврат/накопление от обработчиков.** v1 — обработчики `ничего` (fire-and-
  forget). Свёртка результатов (как редукция §56) — отдельный заход, если нужен.
- **Отписка в Tier 1** — не существует (связь статическая). Нужна отписка →
  это сразу Tier 2.

## Связь с существующим

- Механизм трампулинов и RAII-владения данными (§13/§68) переиспользуется в
  Tier 2 (хранение типизированных обработчиков с данными).
- Десугар-подход Tier 1 — тот же, что `цикл`§46 / range-for §67 / zip-`для_каждого`
  §56: фича исчезает в парсере/кодогене, семантика почти не трогается, 0 рантайма.
