# План: ограниченно, но безопасные указатели

Роадмап расширения указателей Konda БЕЗ borrow-checker. Уточнён по ходу
исследования транспилятора (зонды пограничного поведения).

## Модель: две оси безопасности

Память Konda безопасна по построению: **нет сырого `&`, нет глобалов, нет
замыканий** → ссылку нельзя заалиасить/спрятать. Расширять указатели безопасно
можно ровно по двум осям:

- **Заимствование (second-class references)** — временные не-убегающие ссылки.
  Безопасны структурно (не переживают объект). Существует: `изменяемый`/`вывод`/
  `чтение`-параметры, ссылки на проекции (`изменяемый т.х`, `вывод с[и]`).
- **Владение (single-owner + move)** — владеющие указатели, autofree, move.
  Безопасны существующим move-анализом. Существует: `срез<примитив>` (владеет
  памятью), кадры потоков.

**Граница (НЕ трогать без пересмотра инварианта):** first-class убегающий `&`,
хранение *заимствованного* указателя в поле, возврат указателя неизвестного
провенанса, алиасинг. Это borrow-checker/регионы — сознательно отвергнуты.

## Задачи по сложности

### 🟢 Задача 1 — `чтение` для своих функций ✅ РЕАЛИЗОВАНО (коммит e17763b)
Const-ссылка второго класса и у своих функций (не только `внешняя`). Тело не
пишет в объект (иммутабельность). Кодоген уже был генерическим — снят гейт.
Нулевая рантайм-цена. Тесты + доки готовы.

### 🟡 Задачи 2 + 4 — типы элемента среза (`срез<T*>`, `срез<структура>`)
**Безопасны** (та же срез-машинерия: границы, autofree дескриптора, move; для
структур без владеющих полей деструкции элементов нет). Нулевая рантайм-цена.

**Уточнённый ОБЪЁМ (глубокий — 4 файла):** это не «мелкий парсер», а изменение
базового допущения «элемент среза = токен примитива» по всему коду:
1. *Парсер* (`съесть_тип_` в `разбор.c`): расширить сигнатуру выходами
   `имя_эл`/`строка_эл`/`указ_эл`; в разборе элемента вызвать
   `съесть_именованный_тип` (структура/перечисление) + съесть суффикс `*`.
   **(Прототип этого шага собран и подтверждён рабочим в исследовании.)**
2. *Семантика* (`семантика.c`): структурный путь объявления перехватывает по
   `тип_данных == ТОКЕН_СТРУКТУРА` РАНЬШЕ среза → гейтить его `&& !узел->срез`;
   символ среза должен нести `индекс_структуры` элемента; `выделить`/`клон`-init
   принять struct-элемент; типизировать `с[i].поле` (элемент — структура);
   ИнфоТипа доступа к элементу — с `индекс_структуры`.
3. *Кодоген* (`кодоген.c`): `срез_выделить(N, sizeof(ЭЛЕМ))` — через `эмит_тип`
   (имя структуры / `*` для указателя), не `тип_токена_в_си` (даёт «int»);
   `срез_доступ` каст к `(ЭЛЕМ*)`; `для_каждого`; доступ к полю элемента.
4. *Autofree-гейт:* `срез<структура-с-владеющими-полями>` → **ошибка** (транзитивная
   деструкция элементов — это Задача 7, ВЫСОКАЯ). Для структур из примитивов/
   указателей — как примитивный срез (free дескриптора).

### 🟡 Задача 5 — `Ящик<T>` (одиночный владеющий heap-объект)
Аналог Rust `Box`: куча, один владелец, autofree, move, авто-разыменование.
Закрывает `zalloc(sizeof *d)` (одиночная heap-структура — сейчас kfc-вывод
падает). **Безопасно** (single-owner + move). Зависит от каркаса типов элемента
(Задачи 2/4) — по сути `срез<T>` длины 1 без индексации. Нулевая доп. цена
(аллокация — нужная операция).

### 🟡 Задача 3 — локальные ссылки-псевдонимы (`ссылка п = проекция`)
Именованный локальный алиас на проекцию. **Безопасно** тем же escape-анализом,
что у стековых срезов (нет сырого `&`/глобалов → обход по имени полон, ссылка
не покидает область). Средняя: новый вид объявления + escape-проверка (база
переживает `ссылку`) + кодоген (C-указатель + авто-разыменование во ВСЕХ
позициях использования `п`). Нулевая рантайм-цена.

### 🔴 Задача 6 — borrow-возврат проекции — ПЕРЕКЛАССИФИЦИРОВАНА В ВЫСОКУЮ
**Находка исследования:** это НЕ средняя, а у границы.
- `вернуть &т.х` (интерьер параметра) даёт **первоклассный** указатель, который
  может пережить `т` → нужен анализ времён жизни (borrow-checker).
- `вернуть о.заголовок` (указательное поле) отвергается **корректно**: провенанс
  хранимого указателя неизвестен (мог указывать на освобождённое). Разрешить
  безопасно = отслеживать провенанс полей = снова borrow-checker.
Держим в `небезопасно`/откладываем вместе с Задачами 7/8.

### 🔴 Задача 7 — владеющий указатель/`Ящик` в ПОЛЕ (+ срез структур с владеющими
полями). Транзитивная деструкция, move-через-поле, запрет циклов. ВЫСОКАЯ.

### 🔴 Задача 8 (граница/research) — регионы/lifetimes. Это borrow-checker,
отвергнут. Интрузивные списки/back-pointers остаются в `небезопасно`.

## Рекомендованный порядок и статус

```
Задача 1 (чтение-свои) ✅ СДЕЛАНО
        │
Задачи 2+4 (типы элемента среза) ── ФУНДАМЕНТ, глубокий (4 файла), безопасен
        │
Задача 5 (Ящик<T>) ── зависит от 2/4
Задача 3 (ссылка-локаль) ── независима, на ref-проекциях

Задачи 6, 7, 8 — у границы/за ней (нужен провенанс/lifetimes) — НЕ делаем.
```

**Максимальный безопасно-указательный охват без borrow-checker: 1→5** (владеющие
heap-объекты одиночные и массивами + const-ссылки + локальные алиасы). Покрывает
почти все *владельческие* паттерны C. Заимствующие-убегающие (6) и деревья
владения (7) — за границей, к которой относимся строго.

## Замечание по реализации 2/4

Прототип парсерного шага собран (сигнатура `съесть_тип_` + разбор именованного/
указательного элемента, `срез<Точка>` парсится). Откачен, чтобы не оставлять
полу-фичу (семантика диспетчеризует по `тип_данных` и без шагов 2–4 даёт
запутанную ошибку «выделить только при объявлении среза»). Начинать реализацию —
с этого прототипа, затем семантика→кодоген→autofree-гейт→тесты→доки одним
вертикальным срезом.
