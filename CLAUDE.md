# CLAUDE.md — рабочие правила и решения проекта Konda

Транспилятор `.конда` → C. Русскоязычный язык с целью: **программист не может
допустить ошибку управления памятью**, при этом в релизе — скорость уровня C.

## ГЛАВНОЕ ПРАВИЛО: фиксировать важное в документации

Всё, что должно пережить `/compact` и не «потеряться» между сессиями, **сразу
записывается в документацию или в этот файл** — не держим важное только в
контексте диалога:

- **Принятое пользователем решение** (в т.ч. ответы на AskUserQuestion), смена
  направления, инвариант дизайна → в раздел «Принятые решения» этого файла.
- **Реализованная возможность / архитектурный факт** → в `README.md`
  (пользовательский взгляд) и/или `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md` (внутренний).
- Обновляя код, **сразу актуализируй доки** (в т.ч. §«Что уже/пока не
  поддерживается» и «Ближайший план» в README) — устаревшая дока хуже её
  отсутствия.
- Перед изменением синтаксиса — **сначала расширить тесты** (`tests/run.sh`).

## Инварианты дизайна (не менять без явного согласия пользователя)

1. **Безопасность — статическая, нулевая рантайм-цена.** Любая новая проверка
   безопасности — на этапе компиляции (или тип), чтобы **релиз работал так же
   быстро, как C**. Единственная рантайм-проверка — границы срезов/массивов/argv
   (её сжимаем статическими доказательствами, а не убираем).
2. **Небезопасное — только в `небезопасно { }`** (счётчик `глубина_небезопасно`,
   в C — обычный блок, нулевая цена). За гейтом: сырой указатель
   (индексация/арифметика), реинтерпретация указателя, доступ к члену `союз`а,
   небезопасные функции libc.
3. **`printf` НЕ трогать** — пользователь позже сделает свою stdlib; формат-строка
   передаётся как есть по дизайну.
4. **Глобальных изменяемых переменных НЕТ** — верхний уровень принимает только
   директивы, функции, пространства и типы. Это **несущее** свойство: вместе с
   «нет сырого `&`» и «нет замыканий» оно делает разделяемое изменяемое состояние
   *неназываемым*, откуда и берётся «гонки невозможны по построению» (модель
   потоков опирается на него напрямую). Добавить глобалы = сделать гонки
   выразимыми и молча обрушить безопасность потоков. Константы верхнего уровня —
   отдельная фича, допустимая, только пока они строго иммутабельны.
5. **Максимизировать статические проверки.**

## Основные принципы (выведены из истории коммитов)

- **Фича = полный вертикальный срез в одном коммите.** Каждая возможность идёт
  сразу через `лексер → парсер → семантика → кодоген → IDE-hover` **плюс** тесты в
  `tests/run.sh` **плюс** обновление `README.md` и `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md`.
  В истории почти каждый коммит трогает все четыре — не оставляй фичу без тестов и
  доков. Ловушка парсера: токен, которым может ЗАКАНЧИВАТЬСЯ оператор, обязан быть
  в `токен_завершает_оператор`, иначе перевод строки после него съедается.
- **Предпочитать проверки без рантайма** («Дополнительные проверки без рантайма»,
  «больше статических проверок») — статика вместо рантайм-стоимости везде, где
  можно; рантайм-guard'ы (деление/сдвиг/переполнение) — только в отладке.
- **Безопасность памяти — непрерывная работа.** Регулярные фиксы double-free,
  деструкторов, use-after-move, transitive-destruction; каждый — с тестом-регрессией.
- **Урок (17.07): любой анализ, снимающий проверку, обязан видеть ВСЕ способы
  мутации.** `собрать_изменяемые` собирал только присваивания и не видел
  `изменяемый`/`вывод` — переменная считалась «известной константой», проверка
  границ снималась по ложному основанию, ASan ловил heap-buffer-overflow.
  Мутация без присваивания в коде — это `изменяемый`/`вывод` (и только они:
  глобалов и сырого `&` нет). Тесты — `мутация_вывод`/`мутация_изм`.
- **Безопасен и сам транспилятор.** `cc` запускается через `execvp` с готовым argv
  (не `system()` со строкой — закрыт command injection через имя файла); парсер
  защищён от переполнения стека на патологических выражениях.
- **Русские ключевые слова, контекстные где нужно.** `и`/`или` вместо `&&`/`||`;
  `и` — контекстное (остаётся валидным именем переменной-счётчика). C-запись тоже
  принимается. Новое ключевое слово не должно без нужды отнимать имя у программиста.
- **Диагностики — на русском, с позицией** (`строка`/`колонка` из `Токен`), и в
  **батч-режиме**: семантика собирает все ошибки за прогон (парсер пока стоп-на-первой).
  **Цветной вывод (CLI, `основа.c`):** ошибки — красным, предупреждения — жёлтым,
  плюс строка-источник с кареткой `^` под колонкой. Цвет — только когда `stderr`
  терминал и не задан `NO_COLOR` (при перенаправлении/в тестах — чистый текст,
  прежний формат заголовка «Ошибка транспиляции»/«Предупреждение» сохранён, тесты
  грепают как раньше). Каретка выравнивается по СИМВОЛАМ (UTF-8 продолжающие
  байты столбец не двигают — как в лексере), иначе кириллица сдвигала бы её.
  Сниппет-источник показывается для одиночного файла (при multi-file
  пост-слияние теряет файл-локальность строки — только заголовок). `libkonda_ide`
  НЕ трогаем: он отдаёт структурированные диагностики, терминальную печать не
  делает.
- **Нет сырого `&`.** Мутация переменной вызывающего — через `изменяемый`/`вывод`
  (ref/out, кодоген сам ставит `&`/`*`); возврат указателя — только borrow
  (память переживёт возврат). Так исключены висячие указатели без borrow-checker'а.
- **IDE-first.** Есть стабильный API `libkonda_ide.c` (анализ в памяти без файлов и
  без `cc`) для language server — не ломать его сигнатуры при правках семантики.

## Принятые решения (ответы на AskUserQuestion и смены курса)

- **Null-безопасность (пункт 3 плана): «ненулевые указатели по умолчанию».**
  Обычный `T*` не может быть `нуль` (ни `= нуль`, ни без инициализатора);
  nullable — только `возможно<T*>`, разворот под охранником `если (п != нуль)` или
  `если (п == нуль) … иначе`. Для этого добавлен оператор `!=`.
- **Охват `возможно` — только указатели.** Опция-над-значениями
  (`возможно<целое>` с флагом присутствия) намеренно **отложена** — отдельная
  фича, другое представление.
- **`возможно<T*>` над ИМЕНОВАННЫМИ типами** (структура/перечисление/`внешний
  тип`), не только примитивы. Нужно для интеропа с C: opaque-хендлы
  (`возможно<display*> д = нуль`, потом присвоение из фабрики). Реализовано во
  всех трёх позициях типа (объявление/параметр/возврат): `разобрать_возможно`
  принимает именованный тип через `съесть_именованный_тип`; `нуль` совместим с
  указателем на структуру (правило поднято ДО ветки структуры в
  `совместимы_для_присваивания`); доступ к полю nullable-структуры (`у.поле` =
  `у->поле` в C) — **разыменование**, поэтому под тем же охранником
  `если (у != нуль)`, что и индексация (null-narrowing снимает `может_быть_нуль`).
  Без охранника — ошибка «может быть нулевым». Тесты: `возможно_структура`,
  `возможно_структура_без_охраны`, `структура_указатель_нуль`.
- **Конвертер C→Konda — отдельный проект `konda-from-clang`** (сосед этого репо,
  Python + `clang -ast-dump=json`). В этом репо конвертера **нет**: проверки — в
  транспиляторе, конвертер только переводит и сам себя проверяет прогоном
  транспилятора (verify-by-default). Ручное управление памятью → `malloc`→
  `выделить`/`срез`, `free` снимается (autofree).
- **Интерфейс библиотек (безопасный путь 2):** типизированный `.и` c примитивами,
  `срез`, указателями и владением; транспилятор сам линкует `.so` (rpath).
- **Макросы — только безопасная условная компиляция** (`макросы.c`): `#if/#ifdef/
  #ifndef/#elif/#else/#endif/#define` (+ русские `#если/#опр/#не_опр/#иначе_если/
  #иначе/#конец/#определить`), `-D ИМЯ[=знач]`. Это выбор веток AST по флагам, не
  текстовая подстановка → включённый код проходит все проверки. **Функциональных
  макросов и подстановки значений в код НЕ делать** — небезопасно; для констант — `конст`.
- **Имена в C — как есть, без манглинга/неявных имён.** Пользователь не хочет
  транслитерации/переименования функций: кириллические идентификаторы уходят в C
  как есть (расчёт на UTF-8-идентификаторы C23). Значит роадмап-пункт «стабильная
  транслитерация в ASCII» **снят для функций** — не генерировать неявные имена.
- **Побитовые операции `& | ^ << >> ~` — реализованы** (целочисленные, нулевая
  рантайм-цена, статически безопасны; float/указатель/срез отвергаются). Ложатся
  в инвариант «безопасность статическая, скорость C». Приоритеты как в C.
- **Перегрузка операторов — реализована** (`Тип оператор+(Л а, П б) { … }`;
  `оператор` — контекстное слово). Набор: `+ - * / % == != < > <= >=`.
  Нулевая рантайм-цена: `а + б` → вызов манглированной функции
  `_опер_<опкод>_<тип1>_<тип2>(а, б)`, статически (резолв в семантике по типам
  операндов). Правила статические: ровно 2 параметра **по значению**, хотя бы
  один операнд — **структура** (примитивные операторы не переопределяются);
  `&&`/`||` не перегружаются (короткое замыкание). Заодно закрыта латентная
  дыра «структура `==` структура» (раньше `тип_бинопа` ошибочно принимал за
  `целое32` → битый C). Ложится в инвариант «безопасность статическая,
  скорость C». Детали — `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md` §«Перегрузка
  операторов».
- **Потоки: модель «передача владения», без разделяемого состояния.** (Ранее
  потоки были отложены; курс изменён.) Поток получает данные **только по
  значению или перемещением** (`владеет`-семантика). Разделяемое изменяемое
  состояние **нельзя выразить** → гонки данных невозможны *по построению*,
  статически, с нулевой рантайм-ценой (инвариант №1). Опирается на готовый
  path-sensitive анализ move в `владение.c`. Синтаксис: `поток<T>`,
  `запустить(ф, арг)`, `присоединить(п)`. Статические правила: функция потока
  НЕ может иметь `изменяемый`/`вывод` (это указатели в кадр вызывающего →
  повисли бы + гонка); аргумент-срез перемещается (у запускающего доступа нет);
  `присоединить` потребляет дескриптор (двойной join — use-after-move).
  **Shared-memory модель в стиле Rust отвергнута**: она требует borrow-checker,
  а он сознательно исключён из дизайна Konda.
- **Каналы `канал<T>` — ОТЛОЖЕНЫ** (осознанно, а не «не успели»). Они дают ровно
  одно: общение во время жизни потока (стриминг, пул воркеров, конвейеры).
  Разделение труда: fork-join `запустить`/`присоединить` покрывает независимые
  задачи, а параллелизм данных и map-reduce — `параллельно для` **с редукцией**.
  Цена каналов высока: (1) появляется **рантайм-библиотека** (мьютекс+condvar+
  буфер) — против духа «генератор обычного C без своего рантайма»; (2) вносят
  **взаимоблокировки** — первый класс багов, который Konda статически
  предотвратить НЕ может (обещание «нельзя допустить ошибку памяти» формально
  цело, но защиты нет). Вернуться к ним, когда появится реальная задача со
  стримингом.
  *(Исправлено 17.07: раньше здесь стояло, что fork-join покрывает и map-reduce.
  Это было неверно — reduce был запрещён как «запись во внешнюю переменную», а
  собрать его вручную мешали статическое число потоков, один аргумент и
  отсутствие подсрезов. Обоснование стало правдой только с редукцией.)*
- **Асинхронность (async/await) — ОТЛОЖЕНА**, обоснование то же, что у каналов, и
  сильнее. Каналы отвергнуты за рантайм-библиотеку (мьютекс+condvar); async
  требует рантайма **несопоставимо большего** — цикл событий, epoll, таймеры,
  планировщик. Принять async, оставив каналы отложенными «из-за рантайма», было
  бы непоследовательно. Плюс async решает проблему, которой у языка ещё нет
  (I/O-конкурентность), при нерешённой той, что есть — пригодность имеющегося
  параллелизма. **Связка (не потерять):** если однажды рантайм для async всё же
  принимается, каналы автоматически теряют своё главное возражение и подлежат
  пересмотру — эти два решения стоят и падают вместе. Условие возврата: реальная
  I/O-задача **и** явное решение по рантайму. Роадмап — `ПЛАН_ПАРАЛЛЕЛИЗМА.md`.
- **Типизированные слушатели (`слушатель<T>` + доверенный трамплин) — ДИЗАЙН
  зафиксирован, код НЕ пишем (решение пользователя).** Цель — снять крупнейший
  блокер конвертации GUI-кода: колбэк с `void *data`, кастуемый в теле к типу
  (`struct T *t = data`) — ~68 % небезопасного/непереводимого на weston.
  Механически недоказуемо (каст `void*→T`), но языковая фича с **генерацией
  трамплина** решает по построению: каст уходит в ОДНУ сгенерированную C-функцию,
  а `T` там — тип, заявленный при регистрации и проверенный семантикой. Три
  конструкции: тип слушателя (`внешний слушатель<T> Имя для C_listener {…}`),
  экземпляр (`Имя л = { поле = колбэк }`), регистрация (`слушать(add_listener,
  объект, экземпляр, данные)`). Кодоген — как шимы потоков
  (`кодоген_шимов_потоков`): на экземпляр эмитятся трамплины + C-структура-
  литерал; тела колбэков перестают быть `небезопасно` (первый параметр —
  `изменяемый T` вместо `void*`). Инварианты целы: трамплин инлайнится (нулевая
  цена), `небезопасно` уходит в доверенный сгенерированный код, borrow-checker не
  нужен (тип-безопасность — связыванием на месте `слушать`). **Открытый вопрос —
  ВРЕМЯ ЖИЗНИ `данные`** (колбэк срабатывает после возврата регистратора):
  фаза 1 — тип-безопасность (данные — обязательство пользователя), фаза 2 — RAII-
  владение данными. Потом kfc распознаёт идиому и нацеливается на `слушать`.
  Полная спецификация — `docs/ТИПИЗИРОВАННЫЕ_СЛУШАТЕЛИ.md`.
- **Интероп с C (одобрено 19.07, «с упором на статические проверки, минимум
  рантайма») — четыре конструкции, все с нулевой рантайм-ценой:**
  (1) `внешняя` — прототип C-функции с `изменяемый`/`вывод`/`чтение`; кодоген
  ставит `&` на вызове, C-декларацию даёт `#содержит`-заголовок (свой прототип
  НЕ печатаем — конфликтовал бы со static inline); (2) `внешний тип Имя` —
  непрозрачный C-тип, только через указатель (by-value — статическая ошибка;
  представление: структура без полей с флагом `внешний`); (3) `чтение` —
  const-ссылка (по_ссылке=3; не мутация: конст допустим, связи длины не рвутся).
  **Обновлено (Задача 1 «безопасные указатели»): `чтение` теперь и у СВОИХ
  функций**, не только `внешняя` — second-class const-reference, тело не может
  писать в объект (иммутабельность через флаг `неизменяемый`, ловится проверкой
  конст). Кодоген уже был генерическим (Тип* + `&` на вызове + `*` в теле),
  снят лишь семантический гейт. Нулевая рантайм-цена: большие read-only
  структуры без копии. `чтение` на примитиве — выбор программиста (для структур
  быстрее, для примитива добавляет косвенность). Прежнее «своим функциям — по
  значению» — теперь ОПЦИЯ, а не единственный путь; (4) **глобальные
  `конст`** — строго иммутабельные константы верхнего уровня (примитивы-
  константные выражения, `символ*`-строки, структуры-литералы с колбэками,
  сигнатура колбэка сверяется с `типфункции`-полем, **и `конст`-массивы**
  `конст T ИМЯ[N] = { … }` с элементом-примитивом или `символ*` — иммутабельные
  таблицы charset/строк/вершин, чтение с проверкой границ; структура-элемент и
  многомерность отложены) → `static const` в C. **Инвариант №4 цел**:
  глобальных ПЕРЕМЕННЫХ нет, попытка — понятная ошибка и в парсере, и в семантике. Всё вместе закрывает wayland/GUI-паттерны
  (out-параметры библиотек, opaque-хендлы, listener-структуры). Контекстные
  слова: `внешняя`/`внешний`/`тип`/`чтение` — имена у программиста не отняты.
- **Батч-ошибки парсера — реализованы**: восстановление на границе объявления
  верхнего уровня (следующая строка с колонки 1, начинающая объявление; предел
  32), `разобрать_с_именами_структур_батч(...)`; CLI печатает все. AST после
  восстановления годен только для диагностики (возвращается nullptr).
- **Обобщённые структуры — реализованы** (мономорфизация, тот же проход
  `обобщения.c`, что и обобщённые функции). `структура Пара<T> { T первый … }`,
  использование `Пара<целое32> п` в любой позиции типа (объявление/параметр/поле/
  возврат). Каждый набор тип-аргументов → отдельный C-тип (`Пара_целое32`,
  `Пара_символ_у`), нулевая рантайм-цена (инвариант №1). **Ключ архитектуры —
  порядок фаз:** сперва мономорфизация функций (`подставить` заходит внутрь
  `УЗЕЛ_ТИПОАРГУМЕНТ`, превращая `Пара<T>` в теле специализации в `Пара<целое32>`),
  затем фаза структур обходит уже конкретные ссылки и порождает специализации
  (свой ворклист — для транзитивных полей-структур). Парсер: `разобрать_тип_
  аргументы_типа` после `съесть_именованный_тип`; `начинается_объявление_типа`
  распознаёт `Имя<…>` как объявление только для известной обобщённой структуры
  (иначе `п < x` — сравнение над переменной, чьё имя совпало с типом). **Scope
  v1 (решение пользователя): поля — примитивы/указатели/другие структуры, НЕ
  `срез<T>`** (отдельная итерация, чтобы обобщения не пересекались с autofree/
  деструкцией; `срез<T>`-поле отвергается парсером). Ошибка Konda: арность
  тип-аргументов структуры (с позицией). Тесты: `обобщённая_структура`,
  `обобщённая_структура_функция`, `обобщённая_структура_арность`.
- **Вывод тип-аргументов — реализован** (`макс(1,2)` ≡ `макс<целое32>(1,2)`).
  **Архитектура — ГИБРИД (решение пользователя):** отдельный проход семантики
  `вывести_типоаргументы` в `режим_вывода` типизирует аргументы обобщённых
  вызовов ТЕМ ЖЕ `типизировать_выражение` и дописывает выведенные
  `УЗЕЛ_ТИПОАРГУМЕНТ` ДО мономорфизации; настоящая семантика затем валидирует
  специализацию как обычно. **Охват v1 (решение пользователя): вывод ТОЛЬКО из
  конкретных аргументов**; если тип аргумента сам зависит от неразвёрнутого
  обобщения (поле/переменная обобщённо-структурного типа) — нужны явные `<>`
  (полный «инстанциация при тайп-чеке» отвергнут как крупная перестройка с
  риском для IDE-API). **Три закрытых подводных камня двойного прогона семантики
  (детали — `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md` §обобщения):** (1) кодоген-
  подсказки (`проверка_бинопа`/`безопасный_индекс`/`проверка_аргументов`) не
  пишем в `режим_вывода` — иначе ложная подсказка переживает до кодогена;
  (2) `подготовить_оператор` мутирует токен (не идемпотентен) → оператор-функции
  в проходе вывода пропускаем; (3) `подставить` теперь копирует имя типа ГЛУБОКО
  (`strndup`) — иначе выведенное имя-аргумент повисало бы после освобождения.
  Невыводимый вызов без `<>` → понятная ошибка «укажите явно». Тесты:
  `вывод_типоаргументов`, `вывод_смешанный`, `вывод_невозможен`.
- **Cross-file generics — реализованы.** Сам разворот шаблонов уже был
  cross-file: `слить_программы` объединяет файлы в одно дерево ДО мономорфизации,
  так что `мономорфизировать`/`вывести_типоаргументы` видят все шаблоны и вызовы.
  Единственный пробел был в ПАРСЕРЕ: пред-скан имён обобщённых
  (`собрать_типопараметры`) — пер-файловый, поэтому парсер файла-потребителя не
  знал, что `макс`/`Пара` из соседнего файла — обобщённые, и трактовал `<` как
  сравнение. Решено по образцу `собрать_имена_структур`: новый набор
  `ИменаОбобщённых` (`собрать_имена_обобщённых` — паттерн «ИМЯ<» на глубине
  фигурных = 0, по всем файлам), передаётся в
  `разобрать_с_именами_структур_обобщённых_батч` (старый `…_батч` — обёртка с
  nullptr, сигнатура не сломана; IDE — однофайловый, ему хватает пер-файлового
  пред-скана), сидируется в `р.обобщённые` до `собрать_типопараметры`. Порядок
  файлов не важен (сбор имён — до разбора). Тесты: `обобщ_главный`/`обобщ_модуль`
  (обе перестановки). **Все три обобщённые фичи (структуры, вывод, cross-file) —
  готовы.**
- **`goto` — НЕ реализовывать** (сознательное решение). Конфликтует с ядром
  инвариантов Konda: definite-assignment (прыжок через инициализацию → чтение
  мусора), владение/деструкторы/autofree (прыжок из/в область минует
  RAII-деструкцию → утечка/double-free), move/borrow-анализ. Все текущие анализы
  **структурные** (по дереву if/while/for); безопасный `goto` потребовал бы
  CFG-анализа с потоками по произвольным рёбрам — крупная перестройка, высокий
  риск. Главный use-case («goto cleanup») в Konda **уже не нужен**: срезы
  autofree сами освобождаются при выходе из области. Безопасная альтернатива для
  выхода из вложенных циклов (помеченные `прервать`/`продолжить`) — возможна
  позже как отдельная структурная фича, но не `goto`.
- **Оптимизации `Срез`/`выделить` (A/B/C) — реализованы** (по запросу
  пользователя, все нулевой рантайм-цены, безопасность неизменна). Детали —
  `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md` §«Этап B/E» и README §срезы.
  **(A) Дескриптор `Срез` — 16 байт** (`{данные, длина}`, без `эл_размер`):
  размер элемента известен статически, кодоген передаёт `sizeof(T)` литералом в
  `срез_доступ`/`срез_выделить`/`срез_клон` (как `массив_доступ`). Дешевле
  копировать/двигать, умножение индекса — на компайл-тайм-константу. **Ломает ABI
  готовых `.so` пути-2** → регенерировать `.h`. **(B) Элизия знак-клампа**
  `количество < 0 ? 0` в `выделить`: вариант `срез_выделить_бз` берётся, когда
  количество доказанно ≥ 0 (беззнаковый тип или числовой литерал; семантика
  проставляет знаковость на узел количества). `calloc` всё равно ловит
  переполнение размера. **(C) Стековое размещение срезов** (escape-анализ
  `собрать_стек_срезы`/`срез_не_убегает` в `кодоген.c`): `срез<T> с =
  выделить(литерал)` с `N·sizeof ≤ 4096`, не покидающий область (не
  возвращается/не move/не переприсваивается), → `T _стек_с[N] = {0}` вместо
  `calloc`/`free`. Надёжно по построению (нет сырого `&`/глобалов → срез
  неалиасим → обход по имени полон; нераспознанное использование → консервативно
  куча). Ложное продвижение = use-after-return/double-free, поэтому по умолчанию
  куча; покрыто ASan и negative-тестами. **D (элизия зануления malloc-вместо-
  calloc) — сознательно НЕ делали** (высокий риск, выигрыш мал: ядро отдаёт
  нулевые страницы).
- **Ссылки на проекции — реализованы** (`ф(изменяемый т.х)`, `ф(вывод с[и])`,
  `ф(изменяемый м[1])`, цепочки `т.а.б`; и для `чтение` у `внешняя`). Итог
  анализа «частично безопасных указателей»: модель — **second-class reference**
  (Hylo/Val), расширение ровно на одно измерение без borrow-checker. Безопасно
  по построению: база в кадре вызывающего заморожена на время вызова; нет
  сырого `&`/глобалов/замыканий → ссылке некуда утечь; границы среза — **при
  формировании ссылки** (тот же `срез_доступ`, BCE под охранником работает и
  тут). Статически отвергнуты: временное (`функция()[и]`), проекция `конст`,
  поле-срез (дескриптор владеет памятью), `владеет`-move того же среза в том же
  вызове (обратный порядок ловит обычный use-after-move). Кодоген не менялся
  (`&` + существующая эмиссия lvalue); `собрать_изменяемые` расширять не
  нужно — мутируется содержимое, не переменные (урок 17.07 цел). Дальше НЕ
  идти: первоклассный `&` = времена жизни = borrow-checker (отвергнут).
  Детали — `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md` §6.5; тесты `реф_*`.
- **Типы элемента среза (`срез<структура>`, `срез<T*>`) — реализованы** (Задачи
  2+4 плана безопасных указателей, `docs/ПЛАН_БЕЗОПАСНЫХ_УКАЗАТЕЛЕЙ.md`). Раньше
  элемент среза мог быть только примитивом; теперь — ИМЕНОВАННАЯ структура (по
  значению: `срез<Точка>`, доступ `с[i].поле`, `для_каждого`) или указатель
  (`срез<символ*>` — слайс строк, `срез<Точка*>`). Та же срез-машинерия (границы,
  autofree дескриптора, move/клон); **нулевая рантайм-цена** (инвариант №1).
  **Вертикальный срез по 4 файлам:** парсер `съесть_тип_` (именованный элемент +
  суффикс `*`, `узел->указатели` = косвенность ЭЛЕМЕНТА); семантика (ветку
  объявления структуры гейтим `&& !узел->срез`; символ несёт `индекс_структуры`
  элемента; `совместимы_для_присваивания` для срезов сверяет
  `указатели`+`индекс_структуры` → `срез<A>≠срез<Б>`, `срез<T>≠срез<T*>`); кодоген
  `эмит_тип_элемента` (имя структуры + `*`, не `тип_токена_в_си`→«int»). **Ключ —
  лайфтайм имени:** анализатор освобождается ДО кодогена, поэтому
  `ОписаниеСтруктуры.имя_токен` указывает В ИСХОДНИК (переживает) — по индексу
  восстанавливаем имя типа для каста. **Autofree-гейт (Задача 7 не сделана):**
  `срез<структура-с-владеющими-полями>` (срез/деструктор) → ошибка — срез НЕ
  вызывает деструкторы элементов (транзитивная деструкция), была бы утечка/
  double-free; `срез<структура*>` разрешён (указатели заимствуются, деструкции
  нет). Тесты: `срез_структура`, `срез_указателей`, `срез_структура_владеющая`,
  `срез_структура_несовместимость` (+ ASan/UBSan). Дальше по плану — Задача 5
  (`Ящик<T>` = `срез<T>` длины 1) на этом же каркасе.
- **`Ящик<T>` — одиночный владеющий heap-объект (Задача 5) — реализован.**
  Аналог Rust `Box`: `Ящик<T> б = выделить()` (без арг) → `T* б = calloc(1,
  sizeof(T))`, `б.поле` = `б->поле` (авто-разыменование), autofree `free(б)` при
  выходе, move `Ящик<T> в = б` (источник перемещён, двойного free нет).
  **Реализация — владеющий ненулевой указатель + флаг `ящик`** (НЕ дескриптор):
  парсер даёт `Ящик<T>` = указатель на T (`указ_эл++`) + `узел->ящик`; семантика
  ведёт box ДО веток структуры/среза (символ `ящик`+`владеет_срезом` для
  autofree, `может_быть_нуль=0`, move через ту же машинерию, что срез); кодоген
  `кодоген_объявления_ящика` + `зарегистрировать_ящик_к` (release = `free(б)`, не
  `free(б.данные)`). **Ключевой приём — переиспользование:** доступ к полю
  (`указатели==1`→`->`) и эмиссия типа `T*` уже были — новое только конструктор/
  autofree/move. `ИнфоТипа` НЕ расширяли (box в выражении = обычный `T*`; владение
  на Символе) → 0 предупреждений. **Scope v1:** T — структура **без владеющих
  полей** (иначе транзитивная деструкция Задача 7 → ошибка); примитивы-содержимое,
  фабрики-возврат `Ящик<T>` и `владеет Ящик<T>`-параметры отложены. Нулевая
  доп. цена. Тесты `ящик`/`ящик_uam`/`ящик_влад`/`ящик_арг` (+ASan). Закрывает
  weston-идиому `zalloc(sizeof *x)` (одиночная heap-структура).
- **Аллокатор `--аллокатор=jemalloc|libc` — реализован (дефолт jemalloc).**
  Реализация проще плана с швом: **интерпозиция линковкой**, без изменения
  кодогена. jemalloc → в argv компилятора добавляется `-l:libjemalloc.so.2`
  (версионный soname — работает и без dev-пакета, только с рантайм-либой); он
  ставится ПОСЛЕ источника, поэтому неопределённые `calloc`/`free` программы
  разрешаются в jemalloc, а не libc. `libc` → ничего не линкуем. Всё в
  единственной точке вызова компилятора `скомпилировать_си` ([ввод_вывод.c]).
  **Только для исполняемых файлов**: у `--библиотека` (`.so`) jemalloc НЕ
  навязывается — аллокатор выбирает финальная программа. **На кроссе**
  (`--целевая-архитектура`) без явного `--аллокатор` — авто-`libc` (host-
  jemalloc в target-sysroot нет). Семантика `calloc` (зануление + overflow-
  check) не тронута — интерпозиция её сохраняет. **ASan-сборка — только libc**
  (jemalloc конфликтует с интерцепторами; ASan-прогоны в тестах компилируют
  сгенерированный C напрямую `cc`, минуя эту точку). Фаза 2 (если понадобится) —
  sized-free через `sdallocx`, но она требует шва в прологе (у `Срез` размер
  уже есть); пока не нужна.
- **Кросс-компиляция `--целевая-архитектура=<триплет>` — реализована (пока
  только gcc).** Генерируемый C уже переносим (типы через `stdint`, нет
  инлайн-ассемблера/интринсиков), поэтому кросс — это выбор компилятора в
  единственной точке `скомпилировать_си`, а не переработка кодогена. Триплет →
  компилятор `<триплет>-gcc` (напр. `aarch64-linux-gnu-gcc`; `execvp` ищет по
  PATH — command injection не появляется, argv по-прежнему массив). Без триплета
  — обычный `cc`. **Не сделано (осознанно, v1):** clang (`--target=`+`--sysroot=`);
  библиотеки пути-2 должны быть пред-собраны под цель (их `.so`/rpath — хостовые);
  мелкий host-`sizeof(void*)` в пороге стекового размещения срезов
  ([кодоген.c] `размер_элемента_байт`) — влияет лишь на эвристику продвижения,
  не на корректность.
- **`--только-си` (`--only-c`) — реализован.** Выдаёт `.c` (и `.h`/`.и` для
  библиотеки) и пропускает вызов компилятора. Удобно для инспекции кодогена и
  ручной сборки/кросса чужим тулчейном.
- **Бэктрейс при аварии — реализован (решение пользователя).** Любой guard
  (границы среза/массива/`аргументы`, деление на ноль, переполнение) перед
  `abort` зовёт `[[noreturn]] конда_прервать` (`ПРОЛОГ_ПАНИКИ` в `кодоген.c`):
  `backtrace()` + `backtrace_symbols_fd(2)` (без `malloc`) + `abort`. **Бэктрейс
  ВСЕГДА** (и отладка, и релиз). **Цена на горячем пути — ноль:** печать только
  на пути отказа, один раз, перед `abort`; ложится в инвариант №1 без исключений.
  Явные решения пользователя по флагам: **(1) `-fno-omit-frame-pointer` НЕ
  добавлять** (стоил бы регистра/скорости в релизе; раскрутка идёт по DWARF
  `.eh_frame` — frame pointer не нужен); **(2) размер-влияющие флаги
  (`-rdynamic`/`-funwind-tables`/`-g`) — по умолчанию ВКЛ** (влияют только на
  размер бинарника, не на скорость), снимаются `--без-символов` (`--no-symbols`)
  → бэктрейс остаётся, но кадрами-адресами; полная символикация — `addr2line`.
  Параметр `символы` у `скомпилировать_си`. `execinfo.h` — под
  `#if defined(__GLIBC__)`, иначе деградация до `abort` (переносимость кросса).

   + привязка payload в ветках `выбор`; кодоген — размеченный союз (tag+union),
   нулевая рантайм-цена; поля варианта — примитивы/указатели (без `срез`).
   Дальше на их основе — `Результат<T,E>` и опция-над-значениями (`возможно<значение>`).
2. ✅ **Индексация произвольного lvalue** — реализована для срезов
   (`структура.поле[i]`, цепочки `а.б[i].в[j]`); проверка границ через `срез_доступ`.
   `функция()[i]` запрещён (утечка владеющего временного — присвоить в переменную).
3. ~~Транслитерация имён в ASCII~~ — **снято** (пользователь против манглинга/
   неявных имён; держим кириллицу как есть, C23 UTF-8-идентификаторы).
4. Полнота: ✅ **обобщённые структуры**, ✅ **вывод тип-аргументов** и
   ✅ **cross-file generics** — реализованы (см. «Принятые решения»); осталось —
   массивы (вывод размера, локальный `срез<T> с = массив`), батч-ошибки парсера.

**Параллелизм — статус и роадмап: `ПЛАН_ПАРАЛЛЕЛИЗМА.md`** (там же — чего стоит
каждый следующий шаг и какой инвариант затрагивает). Кратко:
✅ **Потоки** (модель передачи владения, см. «Принятые решения»): `поток<T>`,
`запустить(ф, арг)`, `присоединить(п)` + **авто-join** дескриптора при выходе из
области (RAII, как autofree срезов).
✅ **`параллельно для`** — параллелизм данных: диапазон дробится на
непересекающиеся куски, общения между потоками нет вовсе. Гонки невозможны по
построению; проверено TSan (0 гонок на 10⁶ элементов).
✅ **Редукция** (`редукция(итог)`) — приватный аккумулятор на кусок + свёртка
после join; только целые (float не ассоциативен → результат зависел бы от числа
ядер). Ею map-reduce стал выразим.
✅ **Вызовы чистых функций** в теле `параллельно для` — чистота **выводится**
(глобалов нет → эффект возможен только через `изменяемый`/`вывод`/срез-параметр/
указатель/`небезопасно`/вызов нечистой), новых ключевых слов нет.
Каналы и async — **отложены осознанно** (см. «Принятые решения»).
⚠️ Ограничения v1 (не дыры в безопасности — всё ловится компилятором): число
потоков — константа в исходнике; поток, объявленный в цикле, последователен
(есть предупреждение); ≤ 1 аргумент; `срез` как результат не поддержан.

## Сборка, тесты, санитайзеры

```sh
make                       # сборка libkonda.so + CLI (должно быть 0 предупреждений)
cd tests && ./run.sh       # весь набор → «OK: все тесты прошли»
# ASan/UBSan-сборка CLI (все LIB_SRC + основа.c):
cc -std=gnu23 -g -O0 -fsanitize=address,undefined \
   дин_массив.c токенизатор_лексер.c конвейер.c ввод_вывод.c аст.c разбор.c \
   обобщения.c семантика.c владение.c кодоген.c заголовки.c интерфейс.c макросы.c \
   libkonda_ide.c основа.c -o /tmp/kasan
```

**Санитайзер-прогон транспилятора в `run.sh` (автоматический).** В конце `run.sh`
собирается тот же ASan+UBSan-CLI и через него **бесплатно переганяется весь
корпус `.конда`** (все накопленные фикстуры + песочница `тест.конда`, **плюс
мультифайловые наборы** — путь слияния `слить_программы` и cross-file обобщения,
которые одиночный прогон не трогает; при добавлении мультифайл-теста продублируй
его набор в список `COMBOS`) в режиме
`--только-си`; падение — только на отчёте санитайзера (маркеры `AddressSanitizer`/
`runtime error:`/`SUMMARY:`), не на коде выхода (негативные фикстуры отвергаются
штатно). Так покрыт **сам компилятор** (арена, AST, строки, UTF-8) — инвариант
«безопасен и сам транспилятор»; прежде санитайзился лишь сгенерированный C.
**jemalloc НЕСОВМЕСТИМ с ASan** (перехват malloc/free мимо интерцепторов) →
санитайзер-прогон форсирует `--аллокатор=libc` (при `--только-си` компиляции
выхода нет, но флаг задан явно как инвариант/страховка). Утечки (LSan) намеренно
**не** утверждаются (`detect_leaks=0`): транспилятор короткоживущий (арена +
выход), цель — use-after-free/overflow/переполнение. *Этот прогон сразу поймал
латентный UB: `&а->типыфункций[индекс_структуры]` образовывался при
`индекс_структуры == -1` (сигнатура фп-псевдонима не разрешена в проходе вывода
тип-аргументов) — исправлено гардом `< 0` до индексации, как в присваивании фп.*

**Санитайзер сгенерированного C (.elf) в `run.sh` (автоматический).** Сразу за
прогоном транспилятора — вторая ось: ловим ошибки **кодогена**. Транспилятор-
санитайзер только что заново сгенерировал `вывод/<имя>.c` для каждой фикстуры
(`--только-си` → **отладочный** режим, с guard'ами границ/деления/переполнения,
и с libc); скрипт пересобирает **каждый** такой `.c` напрямую через
`cc -fsanitize=address,undefined` и **запускает** его. Так проверяется, что
СГЕНЕРИРОВАННАЯ программа безопасна по памяти (индексация, срезы, деструкция,
потоки) — прежде так тестировалась ровно одна фикстура (`стек_срез`), теперь весь
корпус. **Почему именно отладочный вывод, а не «как оставили»:** релиз
(`--релиз`) по дизайну снимает guardّы (инвариант №1: скорость C), поэтому релиз-
вывод фикстуры вроде `переполнение_рантайм` содержит сырое переполняющееся
сложение — UBSan бы его поймал, но это **не дефект кодогена**, а принятый
компромисс; прогон транспилятора нормализует всё обратно в отладку, где guard
аккуратно `abort`'ит ДО UB (без маркера санитайзера). **Самоотбор без списков:**
`.c` без `точка_входа` (библиотеки) не слинкуются → пропуск; фикстуры-гарды
штатно `abort`'ят (не маркер санитайзера, код выхода игнорируем); `stdin` из
`/dev/null` + `timeout` против блокировок. jemalloc обходится тем же способом —
компиляция `вывод/*.c` напрямую через `cc` (libc), минуя точку с дефолтным
jemalloc.

Конвейер: `токенизатор_лексер.c` → `разбор.c` → `обобщения.c` (мономорфизация) →
`семантика.c` → `кодоген.c`; собран в `Собранное/libkonda.so`, CLI `основа.c`.
Детали — в `docs/АРХИТЕКТУРА_ТРАНСПИЛЯТОРА.md`, пользовательский обзор — в `README.md`.
